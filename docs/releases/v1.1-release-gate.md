# V1.1 zero-waiver release gate

Use one candidate directory for every record. Candidates with installed-acceptance waivers, missing evidence, non-pass mandatory evidence, failed evidence, or any Release Blocker cannot be sealed.

1. Complete `v1.1-release-gate-record.template.json` with candidate-relative evidence and artifact paths. Record the deployed, pinned `/v1` controlled-service version, passing health evidence, and tested rollback target.
2. Record the independent operator's attestation and the release owner's approval with a Release Blocker count of zero. Known Issues may contain only non-blocking defects and must include impact, scope, workaround, tracking ticket, and target version.
3. Run `powershell -File scripts/seal-v1-1-evidence-bundle.ps1 -CandidateDirectory <candidate> -GateRecord <record.json>`.
4. Run `powershell -File scripts/verify-v1-1-evidence-bundle.ps1 -CandidateDirectory <candidate>` whenever the bundle is handed off. Any digest drift blocks release.
5. From the exact clean candidate commit, run `powershell -File scripts/create-v1-1-release-tag.ps1 -CandidateDirectory <candidate>`. The command refuses to move an existing `v1.1.0` tag.
6. After explicit release-owner approval, verify the downloaded or handed-off installer with `verify-v1-1-distributed-artifact.ps1` and retain its output record alongside the distribution record.

Never rebuild, replace, or retag after `v1.1.0` is created. A post-tag defect pauses distribution and starts a new compatible 1.1.x candidate, Evidence Bundle, approval, and immutable tag.
