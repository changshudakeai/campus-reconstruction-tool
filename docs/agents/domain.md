# Domain Documentation Consumer Rules

本项目采用单一领域上下文。文档不再通过 handoff、PRD、索引和工单层层覆盖；每类文档只承担一种职责。

## 读取顺序

1. `AGENTS.md`：协作规则和开工入口。
2. `docs/product-baseline.md`：当前用户可见产品行为。
3. `CONTEXT.md`：标准术语；例如“方案边界”“边界获取”“候选采集”。
4. `.scratch/v2-implementation/v0.1-end-to-end-mainline-plan.md`：当前执行顺序和下一步。
5. 与当前任务直接相关的最新有效 ADR：决策缘由和架构边界。
6. `docs/module-decisions.md`：按模块快速定位，不得覆盖 ADR。
7. `docs/research/`：仅在需要理解技术选型时阅读；标记 historical 的研究不是现行规则。

## 权威边界

- 产品基线决定“产品现在是什么”。
- 最新有效 ADR 决定“为什么这样设计、有哪些硬边界”。
- 主线计划决定“现在先做什么”。
- 当前工单只决定“这一小步怎么验收”，不能新增产品行为、架构法源或执行优先级。
- historical / superseded / retired 文档只用于追溯。发现冲突时停止采用冲突段落，不新增兼容工单。

## 领域术语维护

- 新增或改变项目特有概念时立即更新 `CONTEXT.md`，定义保持一到两句话。
- 同一概念只保留一个推荐称呼，并写明应避免的旧称。
- `CONTEXT.md` 只放领域词汇，不放实现机制、测试策略或施工记录。
- 当前已经禁止用一个“采集”同时指边界和候选：必须分别写“边界获取”和“候选采集”。

## ADR 使用规则

- 只在决定难以撤销、若无背景会显得意外、并且确实存在权衡时新增 ADR。
- 决策被改变时保留原 ADR 的历史文字，在状态段标记被哪个新 ADR 取代；不得让两个冲突 ADR 同时显示为当前有效。
- 新增 ADR 后同步 README 索引、模块决策索引和必要术语。

## 开工检查

- 先确认任务属于主线当前阶段，不能因旧工单仍写 `backlog` 或 `ready-for-agent` 就自动启动。
- 对照产品基线找用户可见验收；对照 ADR 找技术边界；对照代码确认现状是否已经实现。
- 发现产品问题才询问产品负责人；crate、文件、函数、测试工具等可逆实现问题由 Agent 自行判断。
