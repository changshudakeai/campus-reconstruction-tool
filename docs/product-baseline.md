# V2 当前产品基线

Status: accepted（2026-08-01，产品负责人确认）

## 首版用户旅程

```text
首次设置
  → 通过高德搜索并选择校区
  → 创建或进入方案
  → 获取、绘制或修正确认方案边界（唯一必填项）
  → 立即导出 .schem
```

边界确认后，用户也可以选择继续：

```text
设置自定义朝向（可选）
候选采集（可选）
候选评审（存在候选时可选）
导出包含已保留候选的 .schem
```

## 导出资格

- **方案边界是唯一必填项。**没有有效方案边界时不得导出；边界一经确认，导出入口立即可用。
- **朝向可选。**用户未设置自定义朝向时，系统以地图正北作为 Minecraft 北方；设置自定义朝向后使用该朝向。
- **候选采集可跳过。**它只用于寻找边界内的建筑、道路、水体、植被、体育和其他对象，不决定方案是否可以导出。
- **候选评审可跳过。**没有候选时合法导出；存在候选时，只有具有 Reviewable 资格且被用户保留的候选进入增强导出，待定、剔除和隔离候选均不进入。
- 最小导出生成边界覆盖范围内的平整场地；增强导出在此基础上加入已保留候选生成的初始校园内容。

## 五步工作区

工作区仍保留“边界、朝向、采集、评审、导出”五个清晰入口，但它们不是五个强制关卡：

- 新方案首先要求确认边界；
- 边界确认后，朝向、采集和导出入口可用，用户可以直接进入导出；
- 评审入口在存在可评审候选时提供实际内容；
- 可选步骤未完成不得被显示为错误，也不得阻塞导出。

## 错误和通知

一个用户意图由一个完整用例入口负责到底，但入口内部可以协调多个能力、后台任务、取消、重试和进度。

功能能力产生结构化的成功、失败、进度和诊断事实；应用流程负责组合这些事实并决定本次操作的影响范围；通知能力负责把结果呈现为弹窗、短暂提示或通知中心记录。禁止的是功能模块之间建立未经登记的直接依赖，不是禁止错误和状态在受控接口中传递。

采集失败只暂停本次候选采集，不得使已经确认的方案边界失效，也不得取消该方案的基础导出资格。正式数据保存失败时必须明确告知用户，不能伪装成成功。

## 当前实现差距

截至 2026-08-01，边界与自定义朝向页面已经接入，但代码仍有“朝向必填、无默认值”以及导出页未完成等旧实现。本文描述的是已经确认的目标产品；只有相应工单和验收测试完成后，才能宣称这些行为已经交付。
