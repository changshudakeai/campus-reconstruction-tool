# 10 — 删除旧总接线并锁死架构护栏

**What to build:** 在所有用户流程已经迁移后删除旧总接线、正式运行时内存后备和业务文件超长豁免，并让自动检查阻止同类耦合重新进入 S1。

**Blocked by:** 03 — 迁移启动与设置流程; 04 — 迁移校区、方案、最近记录与回收站; 05 — 迁移方案工作区、步骤导航与边界; 06 — 迁移朝向流程; 07 — 迁移采集与覆盖率检查; 08 — 迁移评审工作台; 09 — 迁移导出完整流程.

**Status:** ready-for-agent

- [ ] 所有 S1 用户操作均已通过对应功能入口工作，旧总接线路径没有调用者。
- [ ] 删除旧总接线实现，不把其内容整体搬到另一个超级文件或超级模块。
- [ ] 删除正式运行时静默切换到内存数据库的路径，测试适配器仍可在测试中使用。
- [ ] 删除 S1 业务协调文件的超长豁免，所有剩余文件满足规模规则或只有经过单独评审的生成内容豁免。
- [ ] S1 不再直接依赖持久化、地图业务实现、Sponge、地基业务、诊断证据组织、数据源、转换、几何、拓扑、Manifest 或生成引擎。
- [ ] 架构检查明确阻止上述依赖重新出现，并覆盖 ADR-0037 的允许与禁止关系。
- [ ] 除依赖图外，测试明确阻止一个 S1 UI 回调依次调用多个功能入口；仅“依赖都在白名单内”或“文件未超 1000 行”不能通过本项。
- [ ] 功能模块之间没有为绕开 S1 而新增横向依赖。
- [ ] 公开接口快照显示每个面向 S1 的功能接口保持小而完整。
- [ ] 全部迁移切片和工作区回归检查通过。
