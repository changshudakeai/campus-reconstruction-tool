# S1 呈现薄壳修复规格

Status: ready-for-agent

依据：ADR-0017、ADR-0025、ADR-0026、ADR-0037、ADR-0038、ADR-0039、ADR-0040

## Problem Statement

用户希望 V2 完整实现已经确认的产品行为，同时避免重演 v1.x“任何功能都集中在一个巨型中心、修改一处牵动全局”的失败。当前 S1 外壳已经直接了解数据库、启动路由、采集、评审、生成、用料和导出的内部步骤，并依靠超长文件豁免继续增长。即使页面暂时可用，这种结构也会使后续功能越来越难修改、难验证，并使单个模块故障影响整个软件。

## Solution

在不改变已确认页面、流程、按钮行为和数据结果的前提下，把 S1 收紧为纯粹的呈现外壳。S1 只绘制页面、保存未提交的页面临时状态、转交用户操作，并显示功能模块返回的页面状态、进度、导航决定和通知。

首次启动、设置、校区与方案、评审、导出分别通过一个完整入口向 S1 提供能力；跨 F4/B2/B14/F7 的采集操作固定由 A1 `collection-flow` 承担，并按 ADR-0040 分开保存原始观测与可重建候选投影。一个用户操作只交给一个入口，操作内部涉及的存储、验证、生成、用料和文件处理由该入口完整承担。不得把现有巨型接线实现原样搬到新的“超级总管”中。

## User Stories

1. 作为用户，我希望结构修复后页面和操作方式保持不变，以便继续按已经确认的流程使用软件。
2. 作为首次使用者，我希望软件一次判断并显示语言与游戏版本设置页，以便不经历闪屏或错误跳转。
3. 作为完成首次设置的用户，我希望软件一次判断并显示校区搜索与最近使用记录，以便直接继续下一步。
4. 作为回访用户，我希望软件根据正式保存的数据进入最近校区的方案页面，以便快速继续工作。
5. 作为用户，我希望五步流程顶部继续同时显示校区名和方案名，以便始终知道自己正在编辑什么。
6. 作为用户，我希望点击“下一步”后得到一致的允许、阻止或提示结果，以免不同页面对完成条件作出不同判断。
7. 作为用户，我希望输入中的临时文字、弹窗开关、滚动位置和当前页面可以正常显示，以便页面交互自然。
8. 作为用户，我希望校区、方案、边界、朝向和评审结果只有一份正式状态，以免界面显示与实际保存内容不一致。
9. 作为用户，我希望点击保存设置后看到正确的成功或失败提示，以便知道内容是否真正保存。
10. 作为用户，我希望执行联网测试后看到独立的测试结果，以便区分“已保存”和“联网可用”。
11. 作为用户，我希望恢复方案后继续停留在回收站并看到“方案已恢复”，以便确认操作完成。
12. 作为用户，我希望所有成功、失败和警告遵循同一套短暂提示、弹窗和通知记录规则，以免不同页面反馈不一致。
13. 作为用户，我希望开始采集后窗口仍可操作并立即显示进度，以免误以为程序卡死。
14. 作为用户，我希望开始导出后窗口仍可操作并看到导出阶段和结果，以便判断是否需要等待或处理错误。
15. 作为用户，我希望本地页面判断立即完成，以便点击后获得及时反馈。
16. 作为用户，我希望联网或较长计算在后台执行，以便界面不会冻结。
17. 作为用户，我希望后台操作的旧结果不会覆盖后来发起的新操作，以便页面不会跳回过期状态。
18. 作为用户，我希望离开正在执行任务的页面时，软件根据该任务的实际情况决定能否离开，以免误停任务或丢失数据。
19. 作为用户，我希望需要确认时看到清楚的影响说明，以便决定继续离开、取消任务或留在当前页面。
20. 作为用户，我希望一个功能发生故障时其他安全功能仍能使用，以免高德地图或导出故障导致整个软件退出。
21. 作为用户，我希望正式数据库无法读取时得到明确错误、重试和故障资料入口，以免误以为自己在编辑正式数据。
22. 作为用户，我希望正式数据无法保存时相关操作停止，以免关闭软件后才发现内容丢失。
23. 作为用户，我希望软件不会在正式运行时偷偷改用临时数据，以免产生无法恢复的假保存结果。
24. 作为用户，我希望点击“开始导出”后由导出功能完整完成生成、版本核对、用料统计和文件写出，以免不同环节出现互相矛盾的结果。
25. 作为用户，我希望点击“开始采集”后由采集功能完整管理数据源、分类、保存和进度，以免采集结果因页面切换而损坏。
26. 作为用户，我希望评审操作由评审功能统一判断和保存，以免卡片状态与最终导出状态不一致。
27. 作为用户，我希望覆盖率检查独立失败时仍可查看已经采集的数据，以免辅助检查阻断主要流程。
28. 作为维护者，我希望修改一个功能时主要只修改对应模块，以便减少无关回归。
29. 作为维护者，我希望每个功能只向 S1 暴露一个小而完整的入口，以便理解和测试调用方式。
30. 作为维护者，我希望 S1 不再直接了解数据库、几何规则、生成规则或用料表，以便这些实现可以独立变化。
31. 作为维护者，我希望架构检查能阻止 S1 重新依赖被禁止的底层模块，以免同类耦合再次出现。
32. 作为维护者，我希望业务接线文件不能通过无限期超长豁免留在主干，以便规模红线真正有效。
33. 作为维护者，我希望每一个迁移工单完成后 S1 都比迁移前更薄，以免积累“以后再拆”的临时代码。
34. 作为维护者，我希望结构迁移与产品行为修正分开验收，以便出现回归时可以准确定位原因。

## Implementation Decisions

- S1 只承担页面呈现、导航呈现、未提交的页面临时状态和桌面适配；不持有正式业务数据。
- S1 不直接打开正式数据库，不执行持久化，不使用内存数据库作为正式运行时后备。
- S1 不判断业务完成条件。能否进入下一步、离开页面、取消任务或继续后台运行，由负责该操作的功能模块返回决定。
- 一个用户可感知的完整操作只跨越一个功能模块的外部接口。功能模块在接口后完整协调自己的内部步骤。
- 不新建一个掌握全部业务细节的全局协调模块，不把现有巨型接线实现原样搬家。
- 首次启动新增或收拢为一个启动接口，一次返回设置页、校区搜索页或方案页面所需的完整着陆结果。
- 设置、校区与方案、采集、评审、覆盖率检查和导出优先深化现有功能模块接口，不在 S1 中为每个底层动作增加转发方法。
- 每个功能模块只有一个面向 S1 的外部接口；内部测试所需替身留在模块内部，不扩张外部接口。
- 模块返回完整页面状态或完整操作结果，不要求 S1 通过多轮零散查询拼装一个页面。
- 导出功能内部协调生成引擎、用料配置、版本校验、Sponge 文件和写出过程；S1 不直接访问 B17/B18。
- 采集功能内部协调数据源、分类、持久化、增量刷新和进度；S1 不直接访问数据源适配、转换和几何实现。
- 采集原始观测永久保留；候选投影记录来源、规范化几何和可评审/已隔离资格。高德 POI 点位不得伪造成建筑轮廓。
- 评审功能只读取 B2 发布的可评审候选，并管理三态、批量操作、确认要求和封账条件；S1 只呈现工作台状态和操作结果。
- 操作结果由执行操作的功能模块描述；通知中心决定短暂提示、错误弹窗或通知记录的呈现方式；S1 只显示。
- 本地判断同步完成；联网和耗时计算异步执行，并立即返回可呈现的处理中状态。
- 后台操作具有可识别的任务身份；过期结果不得覆盖较新的用户操作。
- 单个功能模块失败时只暂停受影响能力。正式数据安全无法保证时，阻止相关操作并提供重试或故障资料入口。
- S1 可以只读使用显示所需的共享类型，以及本地化、通知显示、快捷键、主题、Slint 和 WebView 等呈现能力。
- S1 不直接依赖数据持久化、地图业务实现、Sponge 导出、地基业务实现、诊断证据组织、数据源适配、数据转换、几何验证、拓扑规则、Manifest 或生成引擎。
- 现有行为偏离 ADR 时另立行为修复工单，不在本规格的结构迁移中顺手修改。
- 迁移按用户操作逐条完成。一个迁移工单若引入过渡接线，必须在同一工单删除，不允许遗留新的豁免。
- 现有超长业务接线豁免在迁移完成前逐步缩小，最终删除。自动生成内容可按独立规则评审，不得把业务协调文件视为生成内容。
- 用户可见文字继续通过本地化资源提供，不在新接口或 S1 中硬编码。
- 除 ADR-0040 已明确要求的候选投影、采集批次和资格查询 schema 外，本规格不顺带扩大数据库范围。

## Testing Decisions

- 最高测试接缝是各功能模块面向 S1 的外部接口。调用者测试和模块行为测试都通过同一个接缝进行。
- 首次启动使用一个可替换的启动接口。生产适配器读取正式状态；测试适配器直接返回首次设置、校区搜索、方案页面和失败等结果。
- 设置、校区与方案、采集、评审、覆盖率检查和导出分别提供生产适配器与内存测试适配器，使每个接缝都至少有两个真实用途。
- S1 测试只断言用户可观察结果：显示哪个页面、哪些字段、是否处理中、出现什么通知、是否允许导航。不得检查功能模块内部数据库状态或生成步骤。
- 功能模块测试通过自己的外部接口断言正式结果、错误、进度和导航决定，不越过接口检查私有实现。
- 先为当前已确认行为建立特征测试，再移动实现；每个迁移切片都必须证明用户可观察行为没有变化。
- 启动测试覆盖首次设置、无最近校区、有最近校区、直接进入方案页面、正式数据读取失败和重试。
- 导航测试覆盖允许进入下一步、条件不足、需要确认、任务后台继续和任务阻止离开。
- 异步测试覆盖立即返回处理中、进度更新、成功、失败、取消，以及旧任务结果不覆盖新任务。
- 故障隔离测试覆盖地图失败但设置与方案仍可用、导出失败但已有数据保留、覆盖率检查失败但评审数据可查看。
- 数据安全测试证明生产路径无法打开正式数据库时不会创建或切换到内存数据库，也不会报告保存成功。
- 通知测试覆盖保存成功、联网测试成功或失败、方案恢复、正式保存失败和故障资料入口，验证通知事实与呈现方式分离。
- 架构测试阻止 S1 对禁止基础模块的直接依赖，并验证功能模块之间没有新增横向依赖。
- 公开接口快照显示每个功能模块面向 S1 的接口保持小而明确；新增公开项必须在评审中显式出现。
- 规模检查不再接受 S1 业务协调文件的无限期超长豁免。
- 每个迁移工单运行其涉及模块的测试、S1 呈现测试、架构检查和完整工作区回归测试。

## Out of Scope

- 不改变已经确认的页面布局、五步流程、按钮行为、提示语义或数据结果。
- 不在结构迁移中修正与本规格无关的产品缺陷；这些缺陷单独立票。
- 不新增 V2 功能，不改变现有 ADR 的产品范围。
- 不提供高德离线地图，不抓取或缓存高德地图内容。
- 不在本规格内实现未来可能的 OSM 离线底图、离线搜索索引或离线地址解析。
- 不更换 Rust、Slint、SQLite、WebView 或现有地图服务技术栈。
- 不整体复制 v1.x 代码进入新接口。
- 不增加自动备份、撤销重做或其他已明确暂缓的功能。
- 不重做全项目所有模块；本规格只处理 S1 与其直接使用的功能接口。

## Further Notes

- 当前 S1 的核心接线实现约 3000 行，并直接参与边界验证、采集进度、评审、生成、用料和导出，是本规格必须消除的主要风险。
- 现有导出功能已经具备部分完整操作入口，应优先深化现有入口，而不是在 S1 旁边再增加一层转发。
- 现有设置和方案管理公开操作较零散，规格拆票时应按用户操作收拢，而不是仅按文件拆分。
- ADR-0017、ADR-0025 与架构白名单中的旧授权需要按 ADR-0037 同步收紧。
- README、领域术语表和模块决策索引需要补入 ADR-0037 与 ADR-0038；由于当前任务的 D 盘既有文件写入权限受限，这些同步项在首个文档工单中完成。
