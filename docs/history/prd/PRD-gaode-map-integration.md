# 高德地图正式接入规格（屏 4 地图底图 + 密钥配置）

Status: completed（历史规格；S1 边界已于 2026-08-01 按 ADR-0037 补充说明）

> **架构后续决定**：本文的产品行为继续有效；“壳 → B5”或壳直接使用 B3 业务能力的旧接缝不再有效。地图嵌入和窗口尺寸同步可留在 S1，边界/朝向业务操作必须通过一个完整功能入口。

> 法源声明：本规格是 `docs/adr/0001~0028` 已定决策在高德地图接入场景的投影，
> 重点依据 ADR-0003（技术栈与地图嵌入）、ADR-0004（应用级全局设置）、
> ADR-0007（边界属于方案）、ADR-0008（校区经高德选定、画边界从锚点开始）、
> ADR-0012（必经两步：边界 + 朝向两点参考线，既定交互不变）、
> ADR-0017（B3 职责含坐标拾取与边界绘制）、ADR-0021（弹窗铁律）、
> ADR-0027（五步步骤条）。**若本规格与 ADR 原文不一致，以 ADR 为准，并修正本规格。**
>
> 技术依据：`docs/research/gaode-map-integration-options.md`（2026-07-27 调研，
> 结论：路线 A = JS API 2.0 + wry WebView 嵌入子窗口模式）；
> `.scratch/map-demo/`（2026-07-27 负责人验收通过：地图加载、点击坐标回传 Rust 均正常）。
>
> 产品铁律（负责人口头约定，效力等同验收标准）：**地图必须与主程序共用同一个
> 窗口，禁止 V1 式独立弹出窗口。**

---

## 问题陈述（Problem Statement）

负责人在屏 4「圈边界、定朝向」时面对的是一块空白坐标画布：没有地图，圈边界
像"蒙着眼睛画圈"，界面文字还有重叠；点击画布只是在一个想象中的坐标系里放点，
跟真实校园的位置对不上。

同时，高德密钥（key + 安全密钥）目前在程序里没有正式的安放之处——demo 用的
本地临时文件只是权宜之计，正式功能无法依赖它。

V1 的老形态是地图弹出独立第二个窗口，负责人已明确否决；V2 必须把地图做进
主窗口里，而这一点 demo 尚未验证（demo 是独立窗口形态），是本次最大的技术
未知数。

## 解决方案（Solution）

把真实高德地图**嵌进主窗口的屏 4 区域**（同一个窗口，不弹第二个），点击地图
即落下圈边界控制点；定朝向步骤按 ADR-0012 既定交互，在同一张地图上点两个点
画出参考线。密钥进 F1 设置页统一保管，程序用到地图而密钥未配置时，弹窗引导
负责人去设置页录入。

施工顺序上先做**嵌入探针**：只验证"地图能稳定嵌在屏 4 区域并跟随主窗口"，
别的都不做；探针通了才允许在上面盖边界、朝向的楼。

## 用户故事（User Stories）

1. 作为负责人，我希望打开屏 4 就能看到我学校位置的真实高德地图（以校区锚点
   为初始中心），而不是空白画布，这样我才知道自己在圈哪里。
2. 作为负责人，我希望地图长在主窗口内部、跟着主窗口走，任何时候都不弹出
   第二个窗口。
3. 作为负责人，我希望在地图上点几下就能圈出边界，点位实时连线预览，跟在
   手机上用高德画圈一样自然。
4. 作为负责人，我希望圈错了能撤销最后一个点、能清空重来（沿用现有交互）。
5. 作为负责人，我希望定朝向时在地图上点两个点画出参考线（ADR-0012 既定
   交互），而不是在空白画布上想象方向；也保留输入方位角的方式。
6. 作为负责人，我希望在设置页录入高德 key 和安全密钥，能存住、能改、能
   "测一下通不通"；没配 key 就打开需要地图的页面时，程序弹窗告诉我去哪配，
   而不是静默失败。
7. 作为负责人，我希望 key 错了、网络断了、高德拒绝服务时，程序用弹窗告诉
   我出了什么事、该怎么办（不是一闪而过的横幅）。
8. 作为负责人，我希望拖动、缩放、最大化主窗口时，地图跟得住窗口，不错位、
   不残留、不闪退。
9. 作为负责人，我希望步骤条、按钮、弹窗这些界面元素能正常显示在地图上方，
   点得动（不被地图盖住）。
10. 作为负责人，我希望切换方案时，每个方案的边界和朝向各归各，不串（与
    Step C 的 per-plan 进度模型同一规则）。
11. 作为负责人，我希望屏 4 不再出现文字互相重叠的现象。
12. 作为开发者，我希望所有地图行为只经过 B3 一个缝（页面生成 + 消息协议 +
    错误上报），壳只负责嵌入与转发，未来换地图供应商只改 B3。

## 实现决策（Implementation Decisions）

- **路线锁定**：高德 JS API 2.0 + wry WebView 嵌入（调研路线 A；demo 已验证
  地图加载与点击坐标回传可行）。安全密钥（securityJsCode）必须在加载 JS API
  前注入——新申请的 key 没有安全密钥无法工作，现有 B3 的 v1.2 模板不支持
  安全密钥，必须升级。
- **缝 1（新，唯一新缝）：B3 高德桥接缝**——gaode-client 扩展，承接 ADR-0017
  目录中 B3"坐标拾取、边界绘制"的既定职责：
  - 地图页模板升级 JS API 2.0 + securityJsCode 注入；key 防注入校验沿用
    既有规则（纯字母数字，其余拒绝）。
  - 新增"取点地图页"：点击地图 → `window.ipc.postMessage` 回传 `经度,纬度`
    （demo 已验证的协议）；与既有"校区搜索页"两种页面并存。
  - 桥协议收敛为 wry 内置 `window.ipc.postMessage` 唯一通道；既有
    `window.mcrebuildBridge` 如需保留，经初始化脚本做别名，不另开通道。
  - 地图加载失败 / key 被高德拒绝的检测（脚本错误监听 + 超时心跳）→ 结构化
    错误回传壳层。
  - `centerOn(锚点)` 能力沿用（ADR-0008：画边界从锚点开始）。
- **缝 2（复用）：F1 设置缝**——SettingsManager 增加"高德 key""安全密钥"两个
  应用级设置字段（ADR-0004），存储走 B2 既有设置读写通道（B2 增设两个设置键，
  本机明文存储——高德安全密钥本就设计给浏览器前端可见场景；DPAPI 加密列为
  后续增强）。设置页新增"高德地图密钥"分组与"测试连通性"按钮（经 B3 发起
  轻量探测，结果按 ADR-0021 三级分派）。
- **缝 3（按 ADR-0037 修订）：完整边界功能入口 → B5**——S1 只转发地图点击事件；经纬度由完整边界入口作为边界点
  数据源，替换现有画布像素坐标；B5 已有的 经纬度 ⇄ 墨卡托 ⇄ 平面米 ⇄ MC 块
  换算链路（CoordinateConverter）不变。边界点数据格式从"画布像素"迁移为
  "经纬度"（ADR-0007 边界属于方案；Phase 2 进度尚未持久化，无历史数据迁移
  包袱）。
- **嵌入技术路线（探针的验证对象）**：wry 子窗口嵌入（build_as_child 或
  Windows 原生 HWND 父子关系），把 WebView 贴在屏 4 指定矩形区域；壳负责在
  主窗口移动 / 缩放 / 最大化时同步子窗口的位置与尺寸。已知 winit 版本差
  （Slint 1.17 用 winit 0.30、wry 0.37 用 winit 0.29）需经 raw-window-handle
  或 HWND 桥接，在探针内解决；若版本差无法桥接，允许升级 wry 大版本（评估
  对 deny.toml / CI 的影响后实施）。
- **探针必须回答的四个问题**：
  1. 嵌入能否编译链接（winit 版本差的桥接）；
  2. 地图能否稳定显示在屏 4 指定区域；
  3. 主窗口移动 / 缩放 / 最大化时，地图区域能否跟住（不错位、不残留）；
  4. Slint 控件（步骤条、按钮、弹窗）能否覆盖在地图上方且保持可点（Z-order）。
  任一条失败 → 退路为"浮动顶层窗口视觉贴合"方案（调研报告备选）；但该形态
  是否满足"共用一个窗口"的产品约定属于**产品裁决，必须回报负责人定夺，
  实施方不得擅自采用**。
- **弹窗铁律落点（ADR-0021）**：密钥未配置 / 无效、地图加载失败、高德接口
  拒绝，均属要紧错误 → B7 模态弹窗 + 公告栏留底；禁止横幅通知。
- **朝向状态随搬地图纳入 per-plan 模型**：朝向步骤上地图后，其 UI 状态按
  方案隔离（与 Step C 的 PlanProgressState 同规则），同时消解"朝向 UI 状态
  全局"的旧债。
- **屏 4 布局重做时同步修复字符重叠**，验收标准含"重叠清零"。
- **密钥未配置引导**：进入需要地图的页面（屏 4、校区搜索）而密钥为空时，
  模态弹窗引导去设置页，不静默失败、不显示空白地图。

## 测试决策（Testing Decisions）

- 好测试的标准：只测外部行为（生成的 HTML 字符串、协议解析结果、设置读写
  往返、坐标换算数值），不测内部实现；沿用各 crate 既有 `mod tests` 风格。
- **B3**：模板单测（v2.0 URL、securityJsCode 注入位置先于脚本加载、key 防
  注入拒绝、取点页包含 ipc 回传脚本）；协议解析单测（坐标载荷、错误载荷、
  畸形载荷）。
- **F1**：密钥两字段经 B2 内存库的读写往返单测（沿用 T05 既有模式）。
- **B5**：经纬度边界点 → 平面米 → MC 块的链式换算用例（coordinate.rs 测试
  组扩展）；边界点经纬度化的 BoundaryDrawer 行为用例。
- **壳（无单测传统，负责人手工验收）**：探针四问逐条过；破坏性测试——快速
  连点、拖动窗口过程中点击地图、断网加载、错误 key、窗口最大化 / 还原、
  画自相交多边形点确认（应弹报错而非闪退）、新方案未设朝向时点第③格（应
  为灰色不可点）。
- **验收入口**：桌面「校园复刻工具 - 开发版」图标（ADR-0014）。

## 范围外（Out of Scope）

- GCJ-02（高德坐标系）↔ WGS84（OSM 采集源）对齐策略——边界与校区锚点同源
  高德，内部自洽；采集环节的对齐另案决策（见 Further Notes）。
- 高德 POI 对照体检——ADR-0019 已否决，且不列入未来增强。
- 校区搜索页行为改造——T19B-3 已定案；密钥落地后仅需联调验证真 key 可用。
- injector.rs 拆分及 Middle Man / Repeated Switches 代码气味——另立架构债
  工单。
- 进度持久化（F3 / B2 扩展）——另立工单；本批保持内存模型。
- 密钥 DPAPI 加密存储——后续增强。

## 附注（Further Notes）

- **坐标系差异提醒**：高德是 GCJ-02，OSM 采集源是 WGS84，同一地点两系坐标
  差几十到几百米。本规格内"圈边界"全部发生在高德坐标系内（与校区锚点同源），
  自洽无偏差；但 F4 采集拿 OSM 数据与边界做空间过滤时会遇到对齐问题，需
  另案决策（v1.x 的处理方式待查 `New branch/` 仓库）——这是留给后续工单
  或 grill 的开放问题，本批不解决、也不许暗中错配。
- **技术债归属（已与负责人确认）**：随本批还 3 笔——无地图底图（即本规格
  核心）、屏 4 字符重叠、朝向 UI 状态 per-plan；另立 2 笔——injector.rs 拆分
  （含两个代码气味）、进度持久化；Step B 遗留的两项破坏性测试并入本批新
  验收清单重做。
- **建议拆单顺序**（供 /to-tickets 参考，阻塞边以箭头表示）：
  1. 嵌入探针（无阻塞——最高风险先排雷）；
  2. 密钥配置 F1 设置页（无阻塞——可与探针并行）；
  3. B3 取点页与协议升级（被 ② 阻塞——需要密钥来源）；
  4. 屏 4 圈边界上真地图（被 ①③ 阻塞；顺带还字符重叠债）；
  5. 朝向两点参考线上真地图 + per-plan 收尾（被 ④ 阻塞；ADR-0012 既定交互）。
- **v1.x 参考**：ADR-0003 记"Slint 下高德地图嵌入方案已跑通"，其形态为独立
  窗口（本规格已否决）；v1 的地图页 JS 交互细节可在 `New branch/` 仓库查阅，
  仅作交互参考，不作形态参考。
- **demo 资产处置**：`.scratch/map-demo/` 为一次性验证品，探针工单落地后删除；
  密钥临时文件 `%LOCALAPPDATA%\MCRebuildV2\dev\gaode-demo-keys.txt` 在密钥
  配置工单落地后删除。
