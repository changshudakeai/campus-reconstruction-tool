# ADR-0003：沿用 Rust + Slint 技术栈并复用 v1.x 核心引擎

## 状态

已接受（2026-07-25，产品负责人确认）

## 背景

重写决策确立后，需要选定实现语言与界面框架。产品硬性要求：

1. 用户双击 .exe 即用，无需预装运行环境；
2. 轻快：启动快、内存占用小、安装包小；
3. 能高效处理百万级方块的生成与导出计算。

评估过的语言备选：Java（需运行环境、内存重、桌面 UI 过时）、Python（重计算慢、打包体积大且易被杀软误报）、TypeScript/Electron（内置浏览器内核，安装包与内存与"轻快"目标冲突）、C#（本身合格，但无法复用现有 Rust 资产）。

界面框架备选：egui（工具感过重，不适合面向学生的正式产品）、Tauri + 网页界面（视觉上限最高，但 v1.x 已在 ADR-0031 中从该路线主动撤退，且引入界面-逻辑翻译层与更高内存占用）。

决定性因素：v1.x 中最高价值、调试成熟的核心资产——Sponge V3 导出引擎、Arnis 建筑外观规则、地图查询逻辑——均为 Rust 实现，且 Slint 下的高德地图嵌入方案已经跑通。仅 Rust + Slint 组合可以完整继承这些资产，预计节省 2-4 个月工期。

## 决定

- 实现语言：**Rust**。
- 界面框架：**Slint**（继续采用 Royalty-Free 许可）。
- v1.x 的导出引擎、Arnis 规则、地图查询逻辑经接口适配后迁入 V2 对应模块，禁止简单整体拷贝（必须先剥离 v1.x 的耦合再进入新模块边界）。
- 编译速度问题由 ADR-0001 的模块化拆分解决，与语言选择解耦。

## 产品负责人的附加要求（作为正式需求纳入）

产品负责人明确表示后续要为应用增加动画并支持自定义风格。因此：

1. **动画规范**：按钮、面板、页面切换需有统一的过渡动效，使用 Slint 内置动画系统实现；
2. **主题系统**：颜色与样式集中定义、不写死在各界面中，从第一版起为"自定义风格/换肤"预留接口。

已向产品负责人说明 Slint 的能力边界：可实现流畅精致一档（过渡动画、主题切换、明暗模式），不追求网页级华丽特效（粒子、3D 翻转等）。产品负责人在知情后选择 Slint。

## 后果

- 节省核心引擎重写工期，降低回归风险。
- 界面开发速度慢于网页技术，需在排期中如实反映。
- 屏幕阅读器可访问性是 Slint 已知短板（v1.x 审计已指出），需要在验收标准中单独跟踪。
