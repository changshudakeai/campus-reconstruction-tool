# ADR-0033：建筑轮廓重叠——提醒用户，不自动删除或合并

## 状态

已接受（2026-07-29，产品负责人确认；同日补充：重叠对象可在告知后同时导出）

## 背景

两个并非重复来源的建筑轮廓可能发生重叠，例如教学楼主体与连廊、附楼或建筑分区互相压住一部分。此类重叠既可能来自数据问题，也可能代表真实的建筑结构，软件无法仅凭重叠关系安全判断哪一个应该删除，或两者是否应该合并。

多数据源采到同一真实对象时，仍按 ADR-0013 保留来源证据并在评审后合并；同一对象命中多个类别时，仍按 ADR-0011 的类别优先级只归入一个类别。本 ADR 只处理两个不同建筑对象的轮廓重叠。

## 决定

- B15 检测到两个不同建筑对象的轮廓重叠时，不自动删除任何一个，也不自动把它们合并；
- 两个对象都进入评审，并标注“与另一个建筑重叠”；
- 用户查看其中一个对象时，地图同时高亮这两个重叠对象，帮助用户看清关系；
- 用户仍按现有三态评审规则决定每个对象是保留、剔除还是暂定；
- 用户将重叠的两个对象都设为“保留”后，导出不被阻止；
- 现有导出确认窗口增加“仍有 N 组建筑重叠，将同时生成”，提供“返回评审”和“继续导出”；不为此另弹一个窗口；
- 该提醒不改变原始采集记录，也不代替 ADR-0013 的多来源重复对象合并流程。

## 后果

- 真实存在的连廊、附楼和建筑分区不会被软件误删；
- 用户能直接看到发生重叠的两个对象及其空间关系；
- B15 负责发现并说明疑点，最终取舍仍由用户决定；
- 合理存在的重叠不会被软件强行阻断，但用户在封账导出前会再次看到明确数量；
- 其他包含关系继续在 B15 访谈中决定。
