# Use versioned registered roof generators

All built-in Arnis roof styles and developer-added roof styles use one compile-time Rust registry, addressed by an exact namespaced style identity and version with a typed, validated parameter schema. A generator receives only validated building-local roof inputs, may write only roof blocks through the in-memory block sink, and must expose footprint compatibility checks; unknown styles, unavailable versions, invalid parameters, and incompatible footprints stop generation rather than falling back to a flat roof. In Detailed Building Mode, source-derived or Arnis-inferred styles remain visible suggestions until human confirmation, and any change to their style, version, parameters, or material invalidates that confirmation; Foundation Mode may continue exporting low-detail placeholder roofs. A Detailed Building may contain independently confirmed Roof Zones associated with building parts; undeclared voxel overlap is invalid, while intentional composition requires an explicit parent-child relationship. Each zone keeps a stable identity and independently derived deterministic seed, and any implementation change that may alter voxel output requires a new generator version. An accepted external model keeps its Model-Derived Roof and bypasses the registry unless the user deliberately replaces that roof, which creates new Roof Zones and requires renewed review. The confirmed source, parameters, generator version, and confirmation evidence are retained in provenance so roof fidelity failures remain explainable and reproducible.
