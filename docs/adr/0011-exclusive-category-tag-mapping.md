# ADR-0011：六类数据互斥分类——物理形态铁律 + 标签映射实现

## 状态

已接受（2026-07-25，产品负责人确认；同日修订：新增"其他"类别作为兜底）

## 背景

重构时重新审视 v1.x 的八步工作流（V2 中校区已提到方案外），产品负责人指出类别间存在重叠对象：体育馆既属"建筑"又属"体育"。若不封口会导致同一对象重复采集/生成，或两边都遗漏。

产品负责人进一步质询分类的可落地性：数据源如何知道"有没有屋顶"？并提议按数据源标签（tag）优先划分。

## 决定

### 原则层：物理形态铁律（给人看，裁决一切争议）

每个地图对象**恰好属于一类**，归类看它在 Minecraft 里的生成方式：

- **盖房子的归建筑**（墙+窗+屋顶）：教学楼、宿舍、食堂、**体育馆、游泳馆**（室内）、校门与围墙（构筑物子类）；
- **铺场地的归体育**（地面图案+划线）：操场、跑道、露天球场、无顶看台；
- **成水面的归水域**：湖泊、河道、**露天泳池**；
- 道路、植被同理按生成方式界定；
- **以上五类都装不下的真实对象归"其他"**：校内铁路、电力设施、雕塑纪念物等——"其他"是正式类别（有自己的采集步骤与导出文件夹），不是垃圾桶；其内对象保留原始标签，生成规则按标签家族逐步补齐（如铁路→铁轨方块）。

### 实现层：标签映射表（给机器执行）

1. 分类完全由数据源标签驱动：`building=*`（数据源定义即"有屋顶的结构物"）→ 建筑；`leisure=pitch/track/stadium/sports_centre` 且无 building 标签 → 体育；`leisure=swimming_pool` 且无 building 标签 → 水域；等等；
2. 映射表**集中定义于一处配置**（呼应 ADR-0009 配置化原则），修订类别规则只改映射表；
3. **多标签冲突**：同一对象命中多个类别时按优先级 **建筑 > 体育 > 水域 > 道路 > 植被 > 其他** 取最高类，仅采集一次（"其他"优先级最低，仅在前五类均不命中时兜底）；
4. **标签缺失/无法识别**：不猜测、不静默丢弃，归入"其他"类别并在评审队列中可见，由用户裁决去留（沿用 v1.x 评审机制）。

### 复用依据

v1.x `campus-services` 已实现按 leisure/building 标签分类采集（含测试），V2 继承该机制并按本 ADR 修订映射表。

## 后果

- 消除"体育馆重复生成/双向遗漏"一类的分类事故；铁路等非五大类对象有了正式归宿。
- 争议对象的归属有唯一裁决依据（先查映射表，映射不了进"其他"+评审）。
- 未来泛化（ADR-0009）时扩类别 = 扩映射表，原则不变。
