# ADR-0029：校区边界来源——OSM 自动获取优先，人工圈画兜底，无候选列表

## 状态

已接受（2026-07-28，产品负责人确认）

## 背景

V2 重写初期（T19B-5）因壳层无地图能力，边界圈画落地为"纯坐标画布"妥协形态；
T21–T23 打通高德地图嵌入后，原计划（T24 初稿）是把画布换成真地图、继续纯
人工逐点圈画。产品负责人在 T24 开工前明确指出：v1.x 已验证的正确形态是
**边界从 OSM 数据源自动获取，人工只做调整**——纯人工圈画一个校区需要点击
几十上百个点，属体验倒退，不得作为正式形态。

v1.x 证据链：`campus-services/public_source_v1.rs` 以校区锚点为中心查询
Overpass（`amenity~university|college|school` 的 way/relation），多数学校在
OSM 中自带围墙边界多边形，可直接复用。

## 决定

### 边界获取流程

1. 屏 4 第①步打开时：以校区锚点（ADR-0008）为中心自动查询 Overpass，
   获取 `amenity~university|college|school` 的边界多边形；
2. **无候选列表**：查询返回多个对象时，由程序自动选取最匹配的一条
   （排序规则：包含锚点优先 → 校区名称匹配 → 锚点距离最近），直接绘制在
   高德地图上。不向用户暴露候选选择界面——用户看到的就是"边界已经画好了"，
   不对就改，而不是先做选择题；
3. 用户对自动获取的边界做**人工调整**（地图上拖动顶点增删改），
   调整完成后确认，边界以经纬度存入 B5（ADR-0007：边界属于方案）；
4. **人工圈画兜底**：Overpass 查询失败（断网/超时/服务不可用）或该校区
   在 OSM 中无边界数据时，不阻塞流程——提示后切换为人工逐点圈画模式
   （沿用 T19B-5 既有交互，画布底图换成真地图）。

### 坐标系转换

OSM 返回 WGS-84 坐标，高德地图使用 GCJ-02。边界多边形在绘制前必须经
高德官方坐标转换（`AMap.convertFrom`）处理，禁止直接绘制未转换坐标
（否则边界偏移数百米，肉眼可辨的错误）。

### 职责分层

- 查询发起、多边形提取、坐标转换、地图渲染：地图页（B3 生成的 WebView 内容）；
- 候选排序选取、最终边界校验（自相交/点数不足）、存储与换算：Rust domain 层
  （B3/B5），排序与校验逻辑必须可单测；
- 壳层：仅做嵌入显示与消息桥接（ADR-0017 壳零业务逻辑不变）。

### 与既有决策的关系

- 本 ADR 补充 ADR-0012（"确定边界"为必经第①步）的**实现方式**，不改变其
  必经地位；
- 边界多边形查询属 ADR-0013 OSM 适配器能力的一部分（"查询指定区域 → 返回
  地理对象"），复用 v1.x 已验证的查询逻辑并按其拉宽标签范围的精神保留
  `school` 一级标签；
- 人工圈画兜底路径保留，使本决策对"OSM 无数据校区"零阻塞。

## 后果

- 用户常态路径从"逐点圈画数十次点击"变为"看一眼自动边界 → 微调 → 确认"，
  第①步耗时从分钟级降到秒级；
- 新增 Overpass 网络依赖：断网环境自动退化到人工圈画，体验与 T19B-5 现状
  持平，不产生回归；
- 顶点编辑依赖高德多边形编辑插件（JS API 2.0），属新引入的前端能力，
  其不可用时的兜底同样回退到人工圈画；
- 自动排序规则若选错边界，用户可通过调整或清空重画修正，无错误固化风险。
