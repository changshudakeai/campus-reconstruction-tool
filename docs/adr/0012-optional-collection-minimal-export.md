# ADR-0012：采集非强制——最小路径为"边界→朝向→导出地基"

## 状态

已接受（2026-07-25，产品负责人确认；同日修订：朝向改为必选，新增"其他"类别；后被 ADR-0024 升级："地基"含义由平面底图升级为 Arnis 式完整初始校园）

## 背景

产品负责人明确：六类数据（建筑/道路/水域/植被/体育/其他）的采集**不是强制步骤**。用户可以只圈画学校地基（边界）并设定朝向，然后直接导出地基——这是本程序灵活性的核心。朝向为必选步骤（产品负责人明确纠正，不提供默认值兜底）。

## 决定

方案工作区的任务链调整为"两步必经 + 六类可选 + 一个随时可达的出口"：

- **必经**：① 确定边界 → ② 设定朝向（高德地图上画两点参考线，既定交互不变）。两步完成后，导出即可用；
- **可选**：③ 建筑、④ 道路、⑤ 水域、⑥ 植被、⑦ 体育、⑧ 其他。任何一类都可以跳过；跳过的类别在导出包中不出现；
- **"其他"类别**：收纳五大类装不下的真实对象（如校内铁路、电力设施等），归类规则见 ADR-0011；
- **导出**：⑨ 导出打包当前已有的内容——最少只含地基；`foundation_manifest.json` 清单如实记录本次导出包含/缺失哪些类别；
- 工作区界面仍按任务链呈现进度，但可选步骤显示"可跳过"状态，不阻塞导出入口。

### 与既有决策的关系

- 沿用九步骤的顺序骨架（校区已提到方案外，见 ADR-0008/0010）；
- 采集时的类别互斥与标签映射按 ADR-0011 执行。

### 数据完整性核查要求（实施阶段落实）

1. 采集查询的标签范围按类别配置化，与 ADR-0011 映射表同源管理；查询范围须显著宽于 v1.x（v1.x 缺失：leisure=swimming_pool、barrier 家族〔围墙/校门〕、amenity=parking/fountain、historic=monument、natural=tree/tree_row 等校园常见对象）；
2. 拉取回但映射不上五大类的对象一律归入"其他"类别并在评审中可见，禁止静默丢弃（v1.x classify() 的静默丢弃行为不得带入 V2）；
3. 建立标签覆盖审计工单：对照校园常见对象清单逐项核对查询范围与映射表；同时核对导出清单的类别文件夹与六类采集的一致性（含新增的 /others/ 文件夹）。

## 后果

- "快速出地基"成为最短用户旅程：边界 + 朝向（画一条参考线）后几分钟内可完成首次导出。
- 导出包内容可变，下游（清单格式、导入指引）必须容忍类别缺失。
- 朝向为必选，不存在"无朝向导出"的歧义状态；修改朝向会触发已生成数据的重算，需在界面明确告知影响范围。
