# ADR-0021：通知中心——轻公告栏 + 弹窗铁律

## 状态

已接受（2026-07-25，产品负责人确认）

## 背景

v1.x 后期按产品负责人需求加入了只读通知中心（v1.x ADR-0037，按项目分账）。V2 重新决策其形态，并在访谈中确立了一条覆盖全应用的通知纪律（"弹窗铁律"），该纪律同日触发了 ADR-0019 的修订（体检疑点由横幅升级为弹窗）。

曾考虑并否决：
- **不设公告栏**（消息弹完即逝）——要紧消息错过即查无对证，被否决；
- **重公告栏**（消息可点击跳转到对应页面重试）——每类消息都要接跳转逻辑，工作量与出错面大，留给未来按需提案；
- **每方案各一本账**（v1.x 做法）——跨方案是盲区，"忘了是哪个方案出的事"时要挨个翻，被否决。

## 决定

### 一、弹窗铁律（全应用通知纪律，优先级最高）

**凡是会影响采集数据质量、或导致后续操作无法继续的错误，必须用弹窗（模态，点掉才能继续），禁止使用横幅**——横幅用户根本看不到，也不会去管。

消息按三级分派：

| 等级 | 例子 | 通知方式 |
|------|------|---------|
| **要紧错误**（影响数据质量 / 卡住流程） | 采集中断网、高德接口拒绝、导出失败、数据写入失败、体检疑点（ADR-0019 修订版） | **弹窗**，必须确认 + 留底进公告栏 |
| **普通提示** | 采集完成、自动保存成功、导出完成 | 短暂弹出自动消失（toast）+ 留底进公告栏 |
| **小毛病**（不影响工作） | 某张图未加载 | 不打扰，仅留底进公告栏 |

### 二、轻公告栏：全应用一本账

- 界面常驻铃铛图标，任何页面可点开；
- 所有等级的消息一律留底，按时间倒序一列排开；
- **每条消息带来源标签**（如"方案 2：导出失败"、"应用：设置已保存"），跨方案不混淆；
- **只读 + 可复制**：只能查看和复制文字，不提供点击跳转（跳转留给未来提案）；
- 铃铛上显示未读数角标，点开即清零（实现细节，不再另行决策）。

### 三、留存规则（安全默认值，实现层可调）

公告栏保留最近 200 条或 30 天（先到为准），超出自动清理；清理不需要用户确认（公告栏是留底不是档案库）。

## 后果

- "弹窗铁律"是全应用纪律，约束所有现有与未来模块：任何新功能设计通知方式时，先按三级表对号入座；
- ADR-0019 已按本铁律修订（疑点横幅 → 弹窗）；
- 通知留底需持久化（SQLite，ADR-0002），与方案数据分表存储（消息是应用级账本）；
- 只读设计使通知中心不依赖任何功能模块的内部状态，符合模块化十戒的低耦合要求（ADR-0017，B7 为基础模块）。
