# ADR-0030：重新采集结果——变化优先、全量可查

## 状态

已接受（2026-07-29，产品负责人确认）

## 背景

方案已采集过一次后，用户可能因校园更新、数据源补充或想核对最新情况而再次采集。若把大量完全未变化的对象与真正变化的对象混在一起，用户难以快速判断这次是否值得关注。

## 决定

重新采集完成后，采集页先展示一份变化摘要，分别报出：

- 新增；
- 有变化；
- 本次未找到；
- 未变化。

默认只展开“新增”“有变化”“本次未找到”三类对象；“未变化”对象不在默认结果中铺开，避免掩盖需要关注的内容。

页面必须提供明确的“查看全部”入口，用户可随时查看本次采集涉及的全部对象，包括未变化对象。

“本次未找到”只表达本次数据源没有返回该对象，不得据此静默删除数据。它保留在历史记录中，并从原有评审状态改回“待定”，同时标明“本次未找到、需要确认”；在用户重新决定为“保留”前，它不进入下一次导出。

## 后果

- 用户重新采集后先看到真正需要留意的变化，不必在大量未变化对象中寻找；
- 需要核对全貌时仍可查看全部结果，不丢失透明度；
- 采集结果页需要清楚区分四种计数和三种默认展开项。
