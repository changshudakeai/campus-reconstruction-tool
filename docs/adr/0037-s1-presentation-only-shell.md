# ADR-0037：S1 只承担呈现，不承担业务协调

## 状态

已接受（2026-07-30，产品负责人确认）。本决策收紧 ADR-0017 与 ADR-0025 对 S1 的依赖授权，并确认 ADR-0026 中“S1 不得跨层访问 B17/B18”的约束；跨功能完整操作的代码落点由 ADR-0039 补充。

## 背景

V2 的目标是避免 v1.x 的巨型中心再次出现。现有 S1 接线实现已经同时了解数据库、启动路由、采集、评审、生成、用料和导出的内部步骤，并通过超长文件豁免绕过规模红线。继续在 S1 中拼接这些流程，会让功能模块变成浅层转发，并使外壳重新成为修改任何功能都必须触碰的中心。

## 决定

S1 是**呈现外壳**：只负责绘制页面、保存未提交的页面临时状态、转交用户操作，以及显示功能模块返回的页面状态、进度、导航结果和通知。校区、方案、边界、评审结果等正式业务数据不由 S1 持有，S1 不直接打开正式数据库，不判断业务条件，也不拼接多个基础模块完成一个用户操作。

一个用户可感知的完整操作只跨越一个功能模块的接口。例如 S1 只发出一次“开始导出”，生成方块、核对版本、统计用料和写出文件由 F9 内部协调；S1 不直接访问 B17/B18。启动时，S1 只请求一次着陆结果，不自行读取设置、最近校区或方案数据来组合路由。离开页面、取消或继续后台任务是否安全，也由正在工作的功能模块判断。

本地判断应立即返回。联网或耗时计算在后台执行，S1 立即显示处理状态，窗口不得被冻结。一个功能模块失败时，只暂停受影响的功能；涉及正式数据安全的核心能力失败时，停止相关操作并明确提示。正式数据无法读取或保存时，不得静默切换到临时内存数据；内存数据只用于测试和开发调试。

操作结果由功能模块描述，通知中心决定短暂提示、错误弹窗或通知记录的呈现方式，S1 只负责显示。S1 可以只读使用显示所需的共享类型和呈现能力，但不得直接依赖承担持久化、采集转换、几何规则、生成或导出实现的基础模块。

### “壳接线”的边界澄清（2026-08-01）

本 ADR 所允许的“接线”仅指**构造期接线**：S1 的组合根可以创建实现、把实现注入功能入口、绑定 UI 回调和转发功能入口已经决定好的页面事件。构造期接线不得读取中间业务结果、判断下一步调用谁，或把一个功能入口的结果交给另一个功能入口继续处理。

本 ADR 禁止的是**运行期业务编排**：一个 UI 回调不得先调用 F4、再调用 F7，也不得先调用 F5、再调用 F9。用户点击“采集”时，S1 只调用一次完整的采集操作入口；采集、保存、候选几何处理和采集后覆盖体检均在该边界之后完成。用户点击“导出”时同理，S1 只调用一次完整的导出操作入口。

单个功能足以完成操作时，由该功能入口完整承担；必须组合多个功能或基础模块时，由 ADR-0039 定义的非 S1 应用流程模块拥有完整操作。组合根只负责创建并注入应用流程模块，不得用捕获多个功能对象的回调或 trait 实现把运行期编排留在 S1。旧工单中的“只能经壳接线”，若指壳在运行时依次调用多个功能，均以本澄清为准并停止采用。

## 迁移约束

本次修复只调整内部结构，不改变已经确认的页面、流程、按钮行为和数据结果。发现现有行为偏离 ADR 时，另立工单修正，不混入结构迁移。

不允许以“先跑起来”为理由向 S1 新增临时业务逻辑或新的底层依赖。确需过渡接线时，替换与删除必须在同一工单内完成；验收后的主干不得留下“以后再拆”的代码、无限期豁免或静默后备路径。

## 后果

S1 的接口变小，功能模块在自己的接口后完整承担行为，测试也以该接口的可观察结果为准。现有巨型接线实现需要按用户操作逐条迁出；依赖白名单、文件规模豁免和架构测试必须随迁移收紧。
