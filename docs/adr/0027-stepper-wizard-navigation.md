# ADR-0027：主窗口导航骨架采用步骤条向导式

## 状态

已接受（2026-07-26，UI 决策访谈第 1 轮）；2026-07-29 根据方案工作区访谈增补；2026-08-01 由 ADR-0041 修订步骤解锁规则：边界是唯一必填项，朝向、候选采集和评审不得阻塞导出。

## 背景

T19B 拆分评审时产品负责人指出：此前的 grill-with-docs 访谈只定过行为规则（弹窗铁律、教程四条规矩、三态评审等），**从未决策过主窗口的导航结构、教程内容与按钮布局**。若放任执行代理自由发挥，导航骨架这类"牵一发动全身"的设计错了会导致大面积返工。

历史 PRD 曾把方案内五个环节写成严格线性。ADR-0041 后，五个入口仍适合帮助用户理解工作区，但只有边界是导出前置，其余步骤是可选增强。

候选方案：A 步骤条向导式 / B 侧边栏菜单式 / C 向导式+抽屉菜单混合。

## 决定

**采用方案 A：步骤条向导式。**

- 进入方案后，窗口顶部横向显示步骤条，当前步骤高亮、已完成步骤打勾；主区域整屏显示当前步骤内容。
- 不在主流程内的低频功能（回收站、设置、公告栏等）集中放在窗口右上角小图标区，**图标必须配文字标签**，不使用抽屉/汉堡菜单。
- 否决 B（侧边栏）：与已立的"任务驱动而非配置驱动"原则相悖——多入口并列等于让用户自己猜先点哪个。
- 否决 C（混合式）："抽屉"对非技术用户是额外要学的交互概念，且实现成本最高。

判定理由一句话：用户旅程本来就是一条直线，界面骨架照着直线长，不发明用户用不上的自由度。方案卡片上"已完成 X → 下一步 Y"的进度文案与步骤条状态共用同一套逻辑。

### 子决策（访谈中，逐条补入）

- [x] 步骤条的步骤数量与名称（第 2 轮，2026-07-26 已拍板；2026-08-01 修订必选性）：**五个入口全列——① 方案边界 → ② 自定义朝向（可选）→ ③ 候选采集（可选）→ ④ 候选评审（可选）→ ⑤ 导出**。
  - 保留边界和朝向两个页面，原因是地图交互不同；这不再表示朝向是必填关卡。
  - 五步与 T19B-5（边界+朝向）/T19B-6（采集）/T19B-7（评审）/T19B-8（导出）工单切片一一对应。注意：T19B-5 一张工单实施两个步骤页（圈边界、定朝向各占一格）。
- [x] 步骤间跳转规则（第 3 轮，2026-07-26 已拍板；2026-08-01 由 ADR-0041 修订）：**边界前置、可选入口自由、危险改动确认**。
  - 已完成步骤可自由点击回跳查看；但在回跳页内真正修改边界或朝向时，必须弹确认窗列明下游哪些已生成成果将被重算（复用 collection.orientation_recalc_notice 文案体系），确认后才生效，取消则不落库——符合弹窗铁律（要紧事必须弹窗）。
  - 新方案只有方案边界可用。边界确认后，自定义朝向、候选采集和导出立即可用；评审在存在 Reviewable 候选时显示实际内容。用户无需完成可选步骤即可进入导出。
  - 未确认边界时其余入口置灰；已确认边界后不得再用“前跳上锁”阻止直接导出。
- [x] 右上角辅助入口的具体清单（第 4 轮，2026-07-26 已拍板）：**公告栏 · 回收站 · 切换校区 · 设置，四样全上架**。
  - 四个带文字标签的图标固定右上角，任何页面位置不变（可预测性优于省图标）。
  - 各自存在理由：公告栏——非紧急消息集中地（紧急事走弹窗铁律）；回收站——校园级共享、不属于任何单个步骤页；切换校区——方案深处需要直达选校区页的回门；设置——全局功能含教程重看入口。
  - “采集报告”不在本清单（已定居采集页内）。否决把回收站/切换校区藏进页面内：降低可发现性，层层返回对非技术用户是负担。
- [x] 新手教程步数与每步内容（第 5 轮，2026-07-26 已拍板）：**定为三泡，详见 ADR-0028**（新建方案 · 步骤条总介绍 · 评审页介绍；拆除现有采集完成/导出完成两泡，钩子位置随之重排）。
- [x] 方案打开方式与首屏（第 6 轮，2026-07-27 已拍板）：**单击方案卡片即打开方案；打开后按本 ADR 骨架原样执行**——顶部五格步骤条常驻（当前格高亮、已完成打勾、未解锁置灰不可点），主区域直接整屏显示当前步骤内容（新方案首次打开即圈边界页）。
  - 否决“概览屏中间层”（先看大格子、点格子才进内容）：步骤条本身即概览，多一层多一次点击无增益。
  - 第①格方案边界无任何前置任务，永远处于解锁态（新方案初始进度即“尚未确定范围”）；边界确认后导出入口必须立即可达。
  - 本条取代 T19B-4 工单中“点击卡片本身无操作、双击无反应（T20 再考虑）”的暂定描述；重命名/复制/删除按钮仍在卡片右侧独立区域，与单击打开互不冲突。
- [x] 方案内上下文标识（F3 校区流程复核，2026-07-29 已拍板）：**方案内五个步骤的顶部始终同时显示“校区名 / 方案名”**，让用户在圈边界、定朝向、采集、评审和导出时都能确认当前工作属于哪个校区、哪个方案。
  - 只显示方案名不足以区分不同校区下的同名方案；右上角“切换校区”入口不能代替持续可见的当前上下文。

## 后果

### 正面后果

- T19B-2 至 T19B-8 所有页面有统一的骨架容器，执行代理无自由发挥空间；
- 新手教程可直接"指着步骤条讲"，教程结构与界面结构互相印证；
- 步骤条状态即方案进度，与 F3 方案卡片进度描述（ADR-0018）单一事实来源。

### 负面后果

- 低频功能入口空间受限（右上角图标区），若未来低频功能增多需另行决策；
- 严格线性骨架对将来可能的"非线性精修模式"（未排期）构成约束，届时需修订本 ADR。

### 执行约束

UI 工单实施前必须读取 `docs/product-baseline.md`、ADR-0041 和本 ADR；旧工单与其冲突时停止采用冲突段落。
