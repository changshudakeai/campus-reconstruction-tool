# ADR-0004：首次设置向导与应用级全局设置

## 状态

已接受（2026-07-25，产品负责人确认）；2026-07-29 根据设置模块访谈增补。

## 背景

新用户打开应用后的首个体验环节。产品负责人确定的整体入口流程为：

1. 首次打开 → 完成基本设置（语言、Minecraft 游戏版本等）；
2. 通过搜索结果或"最近使用的校区"选择真实校区；
3. 进入该校区下的方案列表；
4. 打开方案开始工作。

其中"Minecraft 游戏版本设在哪一层"存在两个候选：应用层全局设置，或方案层各自设置。版本影响导出文件格式与方块种类，层级选择直接决定数据结构，事后迁移成本高。

## 决定

- **语言与 Minecraft 游戏版本均为应用级全局设置**，通过下拉菜单选择。
- 所有校区、所有方案统一按全局版本导出；不提供方案级覆盖。
- 当前支持范围：语言仅**中文**；游戏版本仅 **26.1.2**。下拉菜单从第一版起就存在，为未来扩充选项预留位置。
- 全局设置在首次设置向导中完成，之后可在应用设置页修改。
- 首次设置向导沿用“完成设置/继续”流程，不额外提供单独的“保存设置”按钮；进入软件后的常规设置页中，语言或 Minecraft 版本的改动必须点击明确的“保存设置”按钮才写入，直接离开页面不保存未确认改动。
- 常规设置页点击“保存设置”后，改动立即对当前应用生效，不要求重启；成功后按 ADR-0021 给出短暂提示。
- 高德地图凭证中，“Web端（JS API）Key”与配套安全密钥为普通用户必填项；缺少任一项时不得保存，并明确指出缺失项。“高德 Web服务 Key”暂时保留，但必须标注“开发人员使用”，普通用户可留空且不影响保存；它不属于 ADR-0013 正式 OSM/Overture 采集流程的必要配置。
- 设置页提供“清除全部高德密钥”按钮。点击后先弹出确认窗口，明确说明清除后地图功能将暂时不可用，直到重新填写；用户确认后一次清除 Web端 Key、安全密钥和 Web服务 Key 的输入内容及本地已保存值，取消则保持原配置不变。清除立即生效，并短暂提示“高德密钥已清除”。
- “保存密钥”与“测试连通性”分开：保存时只检查必填项和明显格式问题，不依赖当前网络；联网测试由独立按钮触发并实际验证服务。断网时允许先保存已填写内容，保存成功短暂提示“设置已保存”，测试结果另行明确提示成功或失败。
- “测试连通性”始终真实验证普通用户必填的 Web端 Key + 安全密钥；若“开发人员使用”的 Web服务 Key 已填写，同一次测试额外验证该通道。结果分开显示为“地图服务”和“开发用 Web服务”，互不掩盖；Web服务 Key 未填写时显示“未配置”，不算测试失败。
- 连通性测试反馈按影响分级：地图服务失败时弹出确认窗口说明原因；地图服务成功时短暂提示“地图服务连接成功”；开发用 Web服务失败时在结果区标红并给出短暂提示，但不弹阻断窗口；所有已执行的测试均成功时短暂提示“连通性测试成功”。
- 常规设置页提供“默认导出位置”：初始值为当前用户的“文档/校园复刻工具/导出”文件夹；用户可通过“选择文件夹”更换。设置保存后立即生效，之后所有方案默认导出到该位置。
- 导出时允许为本次操作临时选择其他位置，但不修改全局默认导出位置；如需永久更改，必须回到常规设置页保存。
- 默认导出位置不存在、不可访问或不可写时，不静默改到其他位置；弹窗说明“当前导出位置不可用”，提供“选择其他位置”和“取消导出”。临时选择的新位置仍只用于本次导出，不修改全局默认。
- V2 不提供自动备份，也不在设置页提供自动备份开关；ADR-0002 已确认的手动项目打包/导出能力不受影响。
- **即使当前每个下拉菜单只有一个选项，首次设置页仍照常显示**：它同时承担"知情告知"职责，页面附提示文字"请确认你的 Minecraft 游戏版本与此一致，否则导入可能失败"。后续版本扩充语言与游戏版本选项时，该页面无需结构改动。

## 后果

- 学生用户无需在每个方案里操心版本问题，认知负担最小。
- 若未来出现"同一校区需要导出到不同游戏版本"的需求，需新增方案级覆盖机制（向后兼容：方案未设置时继承全局值），届时另立 ADR。
- 数据库中版本字段记录于应用设置存储，不进入方案表。
