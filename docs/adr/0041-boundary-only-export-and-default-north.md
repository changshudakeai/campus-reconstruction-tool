# ADR-0041：方案边界是唯一导出前置，未设置朝向时默认地图正北

## 状态

已接受（2026-08-01，产品负责人确认）。本决策取代 ADR-0012 的“边界与朝向两步必经、朝向无默认值”，并修订 ADR-0024 的最小导出路径和 ADR-0027 的步骤解锁规则。

## 背景

“采集”此前同时被用于“取得方案边界”和“采集边界内候选”，导致文档把不同性质的工作混成一条强制链。产品负责人确认：取得方案边界是导出的必要条件；边界内候选采集和评审是增强初始校园的可选工作。自定义朝向也不应阻塞第一次导出。

## 决定

- 方案边界是导出的唯一必填数据。确认有效边界后，导出入口立即可用。
- 自定义朝向可选；没有自定义朝向时，以地图正北作为 Minecraft 北方。
- 候选采集与候选评审均可跳过。空候选集合是合法导出输入，F9 不得因不存在 B14 候选而拒绝基础导出。
- 最小路径为“选择校区 → 创建或进入方案 → 确认方案边界 → 导出平整场地 `.schem`”。存在候选时，只有 Reviewable 且被保留的候选进入增强导出。
- 五步工作区继续作为清晰入口存在，但不是五个强制关卡：边界确认后至少解锁朝向、候选采集和导出，用户可以直接跳到导出。

## 后果

- 现有“朝向必填、无默认值”的代码、测试、文案和步骤锁需要改为显式默认正北。
- 候选采集失败不影响已经取得的基础导出资格。
- “采集”不再作为同时覆盖边界和候选的含糊术语；统一使用“边界获取”和“候选采集”。
