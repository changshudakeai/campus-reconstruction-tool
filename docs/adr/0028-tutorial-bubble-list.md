# ADR-0028：新手教程气泡清单定为三泡（新建方案 · 步骤条总介绍 · 评审页介绍）

## 状态

已接受（2026-07-26，UI 决策访谈第 5 轮，产品负责人拍板）。

本 ADR 兑现 ADR-0020 的预留承诺——"气泡提示点清单不在该 ADR 固化，留给界面审核阶段决定"。界面骨架现已由 ADR-0027 定稿（五步步骤条向导式），据此定死气泡清单。

## 背景

教程形态与行为规矩已由 ADR-0020 定死：跟练式引导（不上课，真实操作中当场指路）+ 四条规矩（每泡可关 / 一键全跳 / 只教一次 / 设置重看）。唯一未决的是气泡清单本身。

F2（onboarding-tutorial）现状：代码已埋 3 个提示点——`plan_list_intro`（首进方案列表）、`collection_completed`（采集完成）、`export_completed`（导出完成）。

候选方案：A 七泡全程陪跑（每个"第一次"都有气泡）/ B 维持现状三泡 / C 折中五泡。产品负责人否决全部候选，亲自圈定第四种组合。

## 决定

**气泡清单定为以下三泡，不多不少：**

| # | 提示点 | 触发时机 | 气泡大意（正式文案走 zh-CN.json，键前缀 tutorial.） |
|---|--------|----------|--------------------------------------------------|
| 1 | plan_list_intro（保留现有） | 第一次进入方案列表页 | 点这里新建你的第一个方案 |
| 2 | stepper_intro（新增） | 第一次进入方案内、步骤条首次亮相 | 顶上这五格就是全部流程，跟着走就行 |
| 3 | review_intro（新增） | 第一次进入"评审"步骤页 | 每条候选给个态度：要、不要、再想想 |

**同时拆除现有的 `collection_completed`、`export_completed` 两个提示点。**

判定逻辑（负责人拍板理由的忠实记录）：

- **2 号泡是"总导游"**：一句话讲完五格流程，圈边界/定朝向不必单独搭话——格子名字本身就是动词指令；
- **完成类气泡全部多余**：采集完成、导出完成时步骤条打勾、下一格亮起，界面自己会说话；
- **只有三态评审是本软件独创玩法**，第一次见值得单独解释一句。

## 后果

### 正面后果

- 气泡总量最少（3 个），对用户的打扰降到最低，与"任务驱动"原则一致；
- 步骤条（ADR-0027）承担主要领路职责，气泡只补界面自身讲不清的三处，职责边界干净。

### 负面后果与连带改动

- F2 的 `TutorialStep` 枚举需拆两个旧提示点、加两个新提示点（`stepper_intro`、`review_intro`），相关测试与 zh-CN.json 文案键同步调整；
- **原"债务③"三个里程碑钩子的埋设位置作废重排**：
  - 首进方案列表钩子 → 仍在 T19B-4（不变）；
  - ~~采集完成钩子 → T19B-6~~ → 改为**首进方案/步骤条亮相钩子 → T19B-5**；
  - ~~导出完成钩子 → T19B-8~~ → 改为**首进评审页钩子 → T19B-7**；
  - T19B-ui-connection.md 索引与相关子工单的债务③描述需按本 ADR 更新。
- 气泡具体坐标仍按 ADR-0020 规矩在 T19B-8 负责人开发版审核时定稿（债务④不变）。

### 执行约束

实施 F2 改动与钩子埋设的工单必须同时读取 ADR-0020（行为规矩）与本 ADR（清单）；两者冲突时先问负责人，不得擅自取舍。
