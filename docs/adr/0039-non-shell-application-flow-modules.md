# ADR-0039：跨功能完整操作使用非 S1 应用流程模块

## 状态

已接受（2026-08-01，产品负责人确认按 ADR-0037 修正文档并依序实施）。本决策补充 ADR-0017 的模块目录，并给 ADR-0037 的“一个用户操作只跨越一个完整功能入口”指定代码落点。

## 背景

采集操作需要依次完成 F4 采集、B2 正式保存、B14 候选几何处理和 F7 覆盖体检。功能模块之间又必须保持 Cargo 横向零依赖。如果把这些步骤写进 S1，违反 ADR-0037；如果让 F4 直接依赖 F7，违反 ADR-0017；如果只把原逻辑搬进另一个壳文件，仍然没有形成可独立测试的完整操作入口。

## 决定

在 S1 与功能模块层之间增加**应用流程模块**类别。应用流程模块拥有一个用户可感知的完整操作，允许向下依赖完成该操作所需的多个功能模块和基础模块；S1 对每次用户操作只调用该应用流程模块的一个完整接口。功能模块之间继续保持 Cargo 横向零依赖，基础模块也不得反向依赖应用流程模块。

首个应用流程模块为 A1 `collection-flow`，规划路径为 `apps/collection-flow`。它拥有“开始采集”和“查看采集报告”两个用户操作的完整接口，在接口后协调 F4、B2、B14 与 F7，并返回已决定好的页面状态、进度、导航结果和通知事实。S1 只转交输入并显示结果，不读取采集中间数据、不选择下一步调用对象，也不得用捕获 F4/F7 的回调或 trait 实现把同一编排伪装成“构造期注入”。

A1 是一个深模块：外部接口只表达完整用户操作；数据源、持久化、几何验证、覆盖体检、取消、过期结果隔离和失败影响范围均属于其实现。生产 adapter 与测试 adapter 只放在内部 seam，测试通过 A1 的外部接口观察行为，不越过接口检查 F4/B2/B14/F7 的内部调用顺序。

B14 `geometry-validator` 是 A1 生产实现的强制前置能力。B14 未立户、A1 未接管运行期编排、S1 契约测试未证明“一次回调只跨越 A1”之前，M3 不得验收完成。

## 拒绝的方案

- S1 在采集完成回调中依次调用 F4、B2、F7：违反 ADR-0037。
- F4 直接依赖 F7：违反功能模块横向零依赖。
- 在 S1 中实现一个捕获 F4/F7 的 adapter，再称其为构造期接线：运行时代码仍属于 S1，只是换了语法。
- 建立一个包办所有流程的通用总协调模块：会重建 v1.x 巨型中心；应用流程模块必须按完整用户操作划分。

## 后果

规划模块数由 30 增至 31；当前已加入 Workspace 的 crate 数仍为 20，A1 只有在接口评审和 B14 前置完成后才能加入。`xtask arch` 需要识别 A1 层：允许 S1 → A1、A1 → F4/F7/B1/B2/B14，继续禁止 F4 ↔ F7、基础层反向依赖 A1，以及 S1 对采集实现的直接运行期协调。
