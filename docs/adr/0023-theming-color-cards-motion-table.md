# ADR-0023：主题与动画——色卡机制 + 动效表 + Codex 手感基准

## 状态

已接受（2026-07-25，产品负责人确认）

## 背景

ADR-0003 确立"动画与主题系统为正式需求"，本决策细化其范围。v1.x 的病根是颜色号与动画时长散落写死在代码各处（如固定米黄底 #f4f0e5），任何调整都是满地找数字的大翻修。产品负责人两次追问"会不会写死"，据此把"集中管理、禁止散落"定为硬性架构约束。

## 决定

### 一、色卡机制（硬性架构约束）

- 代码**永远不写颜色号**，只写颜色角色名（"背景色""主按钮色""警告色"……）；
- 每套主题是一张独立的**色卡资源文件**；切主题 = 换色卡，代码零改动；
- 微调颜色 = 改色卡一行；新增主题 = 新增一张色卡 + 登记一行；新增颜色角色 = 每张色卡各补一行（唯一多处改动的情形）。

### 二、v2.0.0 出厂两张色卡

- **亮色 + 暗色**，设置中可切换，含"跟随系统"选项；
- 多套皮肤（纸张风、清新绿等）不做，未来从色卡库自然生长，零重写（否决 C 多皮肤：v2.0.0 摊子太大；否决 B 仅亮色：辜负"正式需求"定位）。

### 三、动画浓度分布

- **全局基调：轻动画（微反馈）**——按钮反馈、面板淡入淡出、进度平滑，一律 0.2 秒内；
- **里程碑时刻允许中动画（仅三处）**：首次进入方案列表、采集完成、导出完成——一点仪式感；
- **重动画（表演型）否决**；
- **最高原则**：动画永远不能挡操作，与"无卡顿"（ADR-0016）同级。

### 四、动效表机制（硬性架构约束）

动画 = 舞步（怎么动）+ 节奏（多快、什么曲线、开不开）：

- **节奏全部集中**于一张全局动效表（时长、缓急曲线、开关），代码禁止写死"0.3 秒"之类字面数字；
- **舞步**写在界面代码中（框架现实），但必须引用动效表参数；更换舞步是"改一行"级局部小改，不是翻修；
- **"减少动画"开关**：设置中一键将全部动画归零为瞬时切换（照顾晕动症用户 + 性能兜底）。

### 五、风格基准："Codex 手感"三特征

产品负责人指定以 Codex 应用的动画手感为基准，翻译为三条可执行特征：

1. **快而淡**：短促淡入淡出为主，无大开大合的滑动飞入；
2. **不弹跳**：无橡皮筋/果冻弹性，干脆利落；
3. **安静连贯**：内容"渐渐清晰"而非"蹦出来"；长操作用平滑呼吸感提示，不闪不跳。

### 六、具体舞步的决策流程（沿用 ADR-0020 模式）

- 本 ADR 只锁风格基准与浓度分布，**不固化每处动画的具体舞步**（界面未建，空谈无益）；
- 实施期界面成型后，按基准做出真动画，产品负责人**在开发版**（ADR-0014 快捷方式）中实地体验并拍板；
- 动画验收与界面美观度审核（ADR-0020）合并为同一次审核。

## 后果

- 色卡 + 动效表两项硬约束进入实施期工单验收标准，与文本外置（ADR-0005）、配置集中（ADR-0011）同列为"禁止散落写死"家族；
- 暗色色卡意味着所有界面元素从第一天就要按角色名取色，不存在"先写死再迁移"的过渡态；
- 三个里程碑动画依赖对应功能（方案列表、采集、导出）先行成型，属后期打磨工单；
- "减少动画"开关是全局机制，任何新增动画必须自动受其管辖。
