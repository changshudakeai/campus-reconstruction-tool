# ADR-0002：项目数据存储采用 SQLite

## 状态

已接受（2026-07-25，产品负责人确认）

## 背景

v1.x 使用单一 JSON 文档（Schema2）保存整个项目，每次保存需序列化全量文档并计算 SHA-256 哈希，导致保存卡顿 2-3 秒（见 v1.x ADR-0039）；查询任何子集数据都需要加载和遍历全文件；程序异常退出时存在文件损坏风险。

产品负责人最关心的数据特性（按其确认）：
1. 数据不会因程序崩溃而丢失或损坏；
2. 能快速查询和统计（如按状态筛选建筑地块）。

"能用记事本直接查看文件内容"被确认为非需求。

## 决定

V2 的项目数据统一存储于 **SQLite** 数据库：

- 每个校园项目的数据存放在应用数据目录下的 SQLite 文件中；
- 写操作使用事务，崩溃后自动回滚到最近一致状态；
- 常用查询走索引，保存操作只写变更部分，不再全量序列化；
- 项目导出/备份提供打包功能（把数据库及附件打成便携文件），替代 v1.x 的"手抄 JSON"方式。

## 后果

- 保存与加载性能预期提升一个数量级，为交互响应预算（0.1s 反馈 / 1s 完成）提供基础。
- 用户不能再用文本编辑器直接查看项目文件；需要在应用内提供足够的浏览与导出能力来弥补。
- 需要设计从 v1.x JSON Schema2 到 SQLite 的一次性迁移工具（时间点另行排期）。
