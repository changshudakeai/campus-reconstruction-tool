# ADR-0042：边界直出应用流程归属与交付语义

## 状态

已接受（2026-08-04，M1/F9 边界直出收口）

## 背景

ADR-0037 要求 `desktop-shell` 只呈现状态并转交用户操作，ADR-0039 要求一个完整用户操作由独立功能入口拥有。边界直出同时使用 B5、B18、B17 与 B4，并且需要在后台冻结输入、发布双文件和隔离过期结果，因此不能由 S1 读取中间状态后串接基础模块。

## 决定

1. `apps/export-flow` 是 F9 边界直出的单一应用流程入口。它拥有方案上下文、确认边界、全局版本、输出位置和可选朝向的输入适配，并在 `Start` 返回前取得不可变 `BoundaryExportRequest`。后台 worker 不再读取数据库、S1 session 或可变输入。
2. 该流程内部通过 F9 的稳定端口完成 B5 → B18 → B17 → B4。S1 只提交 `Start`、`Poll` 或离开时的结果过期意图，并呈现 F9 返回的确认、真实阶段进度、成功和结构化失败事实；S1 不组装正式请求，也不复制生成、manifest、Sponge 或坐标转换逻辑。
3. `Boundary` 的公开契约继续支持 `Polygon` 和 `MultiPolygon`。地图 seam 传递 GeoJSON 类型与完整 coordinates；边界确认只负责把用户已确认的几何交给 `export-flow`，B5 负责验证每个分片并将所有外环纳入 footprint。
4. 边界确认是 M1 唯一导出资格。候选、评审和保留候选可以为空；F9 生成边界覆盖范围内的最小平整场地。缺少确认边界、版本不支持/错配、生成、写入、发布或恢复失败均不得产生成功结果。
5. `None` 朝向只在完整 F9 用例内判定为 `MapNorth`；它不改变用户设置状态。自定义朝向由同一用例传给 B5 计算实际导出 footprint，并由 manifest 记录来源与角度。
6. 双文件写入通过可注入的受控文件接口完成 staging、备份、发布、恢复和清理。普通失败必须不留下单边新产物；恢复或清理失败必须显式暴露诊断。离开工作区会使当前交付 generation 过期，旧 worker 的结果只能写入其已冻结的方案输出位置，不能交给新页面或新方案。
7. 不建立通用总协调器。候选采集、候选投影和评审仍由各自的功能/应用流程决策拥有；边界直出流程不得以锚点合成矩形代替已确认边界。

## 后果

- `desktop-shell` 依赖 `export-flow` 的完整能力端口，而不依赖 F9 的基础实现细节。
- `export-flow` 的公共测试通过 `BoundaryExportFlow` 观察 Start/Poll、输入冻结、方案切换和过期结果；F9 的文件测试通过 `ExportFileSystem` 注入发布故障。
- 后续接入候选采集或评审必须提交独立 ADR/模块决策，不能扩张本流程的 M1 边界。

## 依据

- ADR-0024：F9 复用 B18、B17 与 Sponge B4 的完整生成导出链。
- ADR-0037：S1 presentation-only shell。
- ADR-0039：非 shell 应用流程拥有跨模块完整用户操作。
- ADR-0041：边界确认、默认正北和空候选直出规则。
