# ADR-0025：允许 S1 主程序壳直接依赖 B1 共享领域类型

## 状态

已接受（2026-07-26，T01 修正）；依赖授权由 ADR-0037 收紧（2026-07-30）。S1 → B1 的只读共享类型例外仍然有效，但本文不再授权 S1 直接依赖或协调持久化、地图服务、几何规则、生成或导出实现；与本文冲突时以 ADR-0037 为准。

## 背景

ADR-0017 原文中 S1 薄壳的依赖白名单是 `{F1..F9, B2..B7, B9..B11, B17}`，未包含 `shared-domain-types`（B1）模块。ADR-0037 后续收紧了这份白名单：S1 只承担呈现，通过一个功能模块接口完成一次用户操作，不再直接协调底层实现。本 ADR 现在只保留 B1 只读共享类型例外。最初的代码审查发现：

- 着陆结果需要携带校区或方案标识供 S1 导航和显示；S1 只消费功能模块返回的着陆结果，不自行读取设置、最近校区或方案数据；
- S1 需要访问的仅是最底层的领域枚举与标识符类型（`CampusId`、`PlanId`、`ReviewState`、`Category` 等），不含任何业务逻辑或函数调用；
- 若不允许 S1 → B1，必须把类型迁移到另一个"超底座" crate 或通过 B2 间接访问，成本更高且更反直觉。

依据"每次决策都落文档"的纪律，新增本 ADR 记录此例外。

## 决定

### 一、允许的依赖路径

✅ **S1 → B1 只读访问**，仅限以下用途：

| 使用场景 | 允许的类型 | 读取内容 | 禁止操作 |
|---------|-----------|---------|---------|
| 着陆结果呈现与导航 | `CampusId`, `PlanId` | 读取功能模块返回的校区/方案 ID | 不得自行查询、构造新实例或持久化 |
| UI 文本键值对 | `Category` | 用于翻译键、分类标签展示 | 不得修改枚举、不得加变体 |
| 状态展示 | `ReviewState` | "待定"/"保留"/"剔除"的字符串表示 | 不得转态、不得触发评审流程 |
| 错误状态呈现 | `Result<T, E>` | 读取功能模块返回的错误枚举 | 不得隐藏错误详情、不得吞异常 |

约束：**不执行业务逻辑**。所有访问仅限于类型层面（结构体字段读取、枚举匹配、trait 实现中的 `where` 约束）。

### 二、禁止的间接穿越

❌ **禁止通过 B1 作为跳板访问其他模块**：

| 违规方式 | 示例 | 原因 |
|---------|------|------|
| S1 → B1 → F1..F9 | `CampusId::get_plan_list()` | 绕过功能模块职责边界 |
| S1 → B1 → B12..B15 | 通过 B1 构造参数并调用 Overture/Overpass API | 违反"E TL/GIS 层不得被壳直接依赖"的铁律 |
| S1 → B1 → slint | 从 B1 内部类型解构出 Slint 组件指针 | 破坏 UI/业务解耦 |

执法机制：编译器层（未声明依赖即编译失败）、CI 层（xtask arch 断言 S1 依赖 ⊆ 白名单 + 关键禁止边）。

### 三、与其他模块的关系

| 模块 | 允许？ | 说明 |
|------|-------|------|
| F1..F9（功能模块） | ✅ | 每个用户可感知的完整操作只调用一个功能模块接口；S1 不拼接多个功能模块或基础模块 |
| B2（数据持久化） | ❌ | S1 不得直接依赖 B2；正式数据读写由对应功能模块负责 |
| B3..B5（地图、导出与几何实现） | ❌ | S1 不得直接依赖；地图服务、格式导出和几何计算由对应功能模块协调 |
| B6、B7、B9..B11（呈现与运行支持） | ✅ | 仅限本地化、通知、快捷键、主题和诊断等呈现能力，不得借此承载业务判断或正式数据 |
| B12..B15（ETL/GIS） | ❌ | 绝对禁止；必须由 F4/F5/F7/F9 中转 |
| B17/B18（生成与导出实现） | ❌ | S1 不得直接依赖；生成、用料统计与文件写出由 F9 内部协调 |
| slint（UI 框架） | ✅ | 原生支持（S1 唯一的外部依赖） |

## 后果

### 正面后果

- **避免复制共享类型**：功能模块可以用 B1 类型返回完整的页面状态与导航结果，S1 无需重新定义校区、方案或评审状态类型；
- **维护 ADR 一致性与透明度**：避免代码与文档长期不一致导致的混淆（如"为什么实际加了 B1 但没写进 ADR"）。

### 负面后果

- **微弱的跨层风险**：未来有人可能在 B1 里悄悄引入 F1..F9 的 trait 方法（虽然编译期不会拦截，因为 S1 不能直接调）；建议通过 PR 评审强化"B1 必须是纯粹数据类型"的认知。

### 缓解措施

- xtask 架构测试 `arch.rs` 的白名单包括 B1 和必要的呈现能力，同时禁止 S1 直接依赖持久化、地图服务、几何规则、生成与导出实现；
- enforcement.md 以“功能模块返回着陆结果，S1 只负责显示和导航”作为启动接线的最佳实践；
- 每个 PR 中修改 B1 的 public API 时，必须同时检查是否影响 S1 的导入路径。

## 附录：xtask 白名单与 ADR 的一致性校验

```rust
// xtask/src/arch.rs
const SHELL_ALLOWED_MEMBER_DEPS: &[&str] = &[
    // 功能层 (F1-F9)
    "global-settings", ...
    // 基础层（新增例外：B1 shared-domain-types）
    "shared-domain-types", // ← ADR-0025 保留的只读共享类型例外
    "localization",        // ← ADR-0037 允许的呈现能力
    "notification-center", // ← ADR-0037 允许的呈现能力
];
```

白名单的最终形态由 ADR-0037 约束：B1 只读共享类型例外继续有效，但不得恢复对 B2、B3..B5、B12..B15、B17/B18 等业务基础设施的直接依赖。
