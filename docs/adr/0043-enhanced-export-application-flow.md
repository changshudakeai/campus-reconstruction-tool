# ADR-0043：增强导出流程归属与封账消费契约

## 状态

已接受（2026-08-05，M4 增强导出实施）。本决策按 ADR-0042 第 7 条为
“边界直出之后接入候选/评审”补足独立模块决策，并落定 ADR-0040 的 F9
消费路径与封账语义在增强导出中的实现边界。

## 背景

ADR-0041 定义最小导出=边界覆盖平整场地、增强导出=基础+保留候选生成的
初始校园内容；ADR-0040 要求 F9 只消费“封账后状态为保留”的稳定候选标识，
并按同一份规范化候选投影生成，不得从原始观测重建候选；ADR-0042 明确边界
直出流程不得扩张，后续接入候选/评审必须提交独立决策。

M4 需要回答两个问题：增强导出这个完整用户操作由哪个模块拥有；以及 F9
如何在不依赖 F5、不绕过 B2 资格的前提下拿到保留候选与封账摘要。

## 决定

### 一、流程归属：A2 `export-flow` 增加增强导出入口，不新建 crate

- 增强导出复用 A2 的 Start/轮询/过期/离开生命周期、Start 前不可变输入
  冻结，以及 F9 `ExportFileSystem` 的 staging/备份/发布/恢复故障注入管线。
  M1 边界直出与增强导出共享同一套“后台完整用例 → S1 轮询 → 离开过期”
  操作形态，新建 crate 只会复制生命周期与失败回滚机制，并让两个流程在
  “谁拥有导出输入”上相互竞争。
- A2 新增公开入口 `start_enhanced()`：独立完整用户操作，直接可测；S1 的
  导出按钮仍只提交一次 `start()` 意图，由 A2 依据 B2 封账事实在内部路由
  （存在已封账保留候选时走增强导出，否则保持 M1 边界直出）。S1 不判断
  业务条件，不读取 B2 中间状态（ADR-0037/0039）。
- 不改变 M1 边界直出行为：`BoundaryExportPort`、`BoundaryExportRequest`
  与既有 `start()` 路径保持原样；增强路径是独立用例，不向边界直出注入
  候选输入，也不扩张 ADR-0042 的 M1 边界。

### 二、封账语义：只有真实候选评审批次才封账

- 封账仍由 F5 评审工作台在用户确认时执行（`ReviewWorkbench::seal` 经
  B2 `ReviewDecisionsApi` 单事务写回）；A2/F9 导出路径**不调用封账**，
  因此基础导出不会制造空封账记录，也不存在“为了导出而伪造评审”的路径。
- 增强导出的输入事实全部来自 B2：`review_decisions` 中状态为保留的稳定
  候选标识 + 当前已发布候选批次中的同一份规范化投影。导出摘要（保留/
  待定/剔除计数）由应用流程从 B2 读取后传入 F9；F9 不依赖 F5。
- 无评审批次、无保留候选时，A2 保持边界直出：manifest 的候选事实为空、
  导出类型记为基础导出。

### 三、F9 消费契约（ADR-0040）

- F9 新增增强能力端口 `EnhancedExportPort`，经窄端口 `CandidateExportReader`
  只按稳定候选标识读取规范化候选投影（类别、展示标签、形状种类与坐标），
  并复核当前投影的 `Reviewable` 资格；读取不到投影或投影已隔离时明确失败，
  不静默跳过（否则 manifest 计数将失真）。
- 禁止路径：查询原始观测、按标签或原始 JSON 重建几何、把隔离对象或
  无投影原始观测放入导出、把保留计数与候选列表不一致伪装成成功。
- 候选几何到 Minecraft 块坐标的换算归 B5：F9 复用 B5 的边界投影上下文，
  把候选多边形投影到与边界同一块坐标系，按外接范围计算尺寸与落位。

### 四、manifest 如实区分基础/增强导出

- `FoundationManifest` 新增 `exportKind`（`base`/`enhanced`）与
  `candidateFacts.keepByCategory`（类别 + 保留数量）；`CandidateFacts`
  继续如实记录候选投影数、评审决定数与保留数。无候选时保持空事实并标记
  基础导出。

## 拒绝的方案

- 新建独立应用流程 crate 承接增强导出：与 A2 的职责重叠，无法说明
  “为什么 A2 不合适”，只会重复生命周期与失败语义。
- 让 S1 依据“是否有保留候选”选择 `start_enhanced()`：把业务条件判断
  留在壳里，违反 ADR-0037；A2 内部路由后 S1 仍只提交一次开始意图。
- F9 直接依赖 F5 读取封账摘要：制造功能模块横向边；摘要由 A2 从 B2
  读取后传入，F9 保持对 F5 零依赖。
- 封账摘要为空时静默退回基础导出：数据读取失败必须结构化失败呈现，
  不提供静默后备路径。

## 后果

- `export-flow`（A2）新增对 B2 `data-persistence` 的常规依赖，经 B2 公开
  trait 读取封账终态与候选投影；A1/A2 同层应用流程共用同一 B2 连接池语义。
- `export-console`（F9）新增增强能力端口、候选投影读者 seam 与错误变体；
  public-api 快照随 PR 更新。
- `foundation-mode`（B5）新增边界投影上下文与候选块坐标外接范围 API；
  public-api 快照随 PR 更新。
- S1 导出页在存在已封账保留候选时显示增强导出内容提示（结构化计数 +
  类别，全部走 zh-CN.json 文本键），按钮仍只转发一次开始意图。

## 依据

- ADR-0040：候选资格是评审与导出的唯一入口闸门；F9 只消费封账后保留
  标识与同一份规范化投影。
- ADR-0041：存在候选时只有 Reviewable 且被保留的候选进入增强导出；
  空候选是合法基础导出输入。
- ADR-0042：边界直出流程不得扩张；本决策即其后缀的独立模块决策。
- ADR-0024：F9 复用 B18 → B17 → B4 完整生成导出链。
- ADR-0037/0039：S1 只呈现与转发；完整操作用例由应用流程承担。
