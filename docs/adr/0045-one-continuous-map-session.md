# ADR-0045：一个方案只使用一段连续地图会话

Status: accepted（2026-08-17，产品负责人确认）

## 背景

方案工作区的边界、朝向和评审都依赖地图。现有实现把它们当成不同页面分别创建、
隐藏和恢复地图，调用方还需要知道当前是哪种地图、是否可见、何时销毁、弹窗关闭后
恢复哪一页，以及应发送哪段 JavaScript。过去几轮地图修复因此反复同时修改工作区、
WebView 生命周期和地图页面脚本，用户切换步骤时也可能丢失位置、缩放或未完成现场。

产品负责人确认：使用一个方案期间，用户应感觉自己一直在使用**同一张地图**，而不
是在不同步骤反复打开几张彼此无关的地图。地图是边界、朝向和地图评审的必要能力；
不围绕极少发生的加载失败扩建复杂后备流程。

## 决策

1. 桌面端建立一个**地图会话（Map Session）**。它在一个小接口后完整拥有地图的
   创建、步骤切换、暂时隐藏、弹窗遮挡、恢复、代际淘汰、延迟销毁和消息协议。
   工作区调用方只表达“我要显示边界/朝向/评审”和结构化操作，不再自行判断地图
   种类、可见性或拼接原始 JavaScript。
2. 同一方案内保持连续现场：
   - 边界与朝向共享校园范围的视野；
   - 评审单独记住当前候选、位置和缩放；
   - 进入暂时不需要地图的采集或导出步骤时可以隐藏地图，但不得清空上述现场；
   - 切换方案必须清除上一方案的临时视野和候选选择，禁止串到新方案。
3. 边界已有未确认修改时，切到评审或导出前必须让用户选择“继续编辑”或“放弃修改
   并切换”。不得一边保留未确认草稿，一边让下游继续使用旧边界而不说明。
4. 弹窗始终在地图之上并独占输入。关闭或取消后恢复同一步骤、位置、缩放和未完成
   工作；只有用户明确选择放弃时才清除草稿。
5. 地图暂时不可用时，明确说明地图相关操作不可继续；不得伪造边界、朝向或地图
   评审结果。已经确认并保存的正式边界、朝向和评审数据仍然有效，已有有效边界的
   方案仍可按 ADR-0041 导出。此处只保留清晰失败与重试，不新增离线地图或复杂降级。
6. 高德 HTML 页面和 wry/WebView2 是地图会话背后的适配器。受 wry 能力限制，内部
   可以安全地重建 WebView，但必须由地图会话恢复用户现场；“同一张地图”指连续的
   用户会话，不要求把某个原生窗口对象永久留在内存里。
7. 地图会话属于 S1 的呈现基础设施：可以保存未提交的页面临时状态并转交事件，但
   不持有正式方案数据、不决定导出资格，也不承担采集或评审业务编排，继续遵守
   ADR-0037。

## 后果

- 调用方不再同时理解页面种类、WebView2 销毁时机、弹窗恢复和原始脚本协议；地图
  生命周期问题在一处修复即可覆盖边界、朝向和评审。
- 地图会话需要为步骤现场和方案身份增加明确的状态与契约测试；真实 WebView2 仍需
  用既有真机剧本抽查焦点、遮挡和地图恢复。
- 原 T46、T47、T48 的按文件拆分方案合并为一个地图会话工单；高德页面若已经是
  小入口、大实现的适配器，不为追求行数机械拆散。
