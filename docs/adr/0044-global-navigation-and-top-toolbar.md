# ADR-0044：全局返回历史栈与顶部工具栏布局

Status: accepted（2026-08-17，产品负责人确认）

## 背景

五步工作区之外的通知中心、回收站、设置、校区选择等页面缺少一致的返回入口；
顶部工具栏把“返回方案列表、通知中心、切换校区、回收站、设置”堆在一排，
主次不分。另：通知中心按钮从工作区点击后跳转失败（根因：跳转时未隐藏地图
WebView 子窗口）。

调研结论（`docs/research/nav-workspace-layout-forms.md`，一手官方规范）：
Fluent 推荐 ≤5 个同级顶级入口用顶部导航；HIG/Material/Carbon 一致建议
左上角返回 + 上下文标题、右上角高频操作、低频操作收进溢出菜单、返回采用
历史栈逐层退。

## 决策

1. 全局导航采用**历史栈（逐层返回）**：每页左上角返回按钮返回“进入该页时的
   上一页”，从哪儿进、从哪儿出；无上一页（首启向导、校区选择从零进入）不显示。
2. 顶部工具栏：左上角 = 返回 + 上下文标题（工作区显示校区/方案名）；
   右上角 = 高频操作（通知、设置）常驻；低频操作（回收站、切换校区）收进
   “…”溢出菜单，菜单项带文字标签。
3. 五步顶部步骤条保持现状（≤5 个同级入口用顶部导航），不改为左侧导航。
4. 任何页面切换离开工作区前必须隐藏地图 WebView 子窗口（修复通知中心跳转
   失败；与 T34/T35/T36/T40 的 WebView 生命周期机制一致）。

## 后果

- 正向：导航一致、可预期；通知中心/回收站/设置可达且可逐层返回；地图子窗口
  不再遮挡目标页面。
- 约束：返回语义由历史栈统一管理；校区选择作为入口页无返回；工作区返回时
  恢复方案与步骤（依赖工作区会话状态，跨重启恢复由“工作现场恢复”工单承担）。
