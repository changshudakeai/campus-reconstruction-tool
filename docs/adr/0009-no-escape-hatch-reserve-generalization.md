# ADR-0009：搜索无结果不设逃生通道，但为泛化复刻预留扩展点

## 状态

已接受（2026-07-25，产品负责人确认）

## 背景

ADR-0008 确定校区只能从高德搜索结果中选定。需要决定搜索无结果时的处理方式。

同时，产品负责人披露长期规划：未来版本要把应用从"学校复刻工具"扩展为"调用地图上的任意数据、在 Minecraft 中还原真实世界"的通用工具。本决策需在不增加当前复杂度的前提下为此保留后路。

## 决定

### 当前行为（V2 首发）

- 搜索无结果时仅显示明确提示（"没有找到匹配的学校，请检查名称后重试"），**不提供手动定位/自由命名的逃生通道**；
- 理由：高德对学校覆盖率极高，逃生通道会破坏"校区数据全部来自真实地点"的原则，且为极小概率场景引入常态维护成本；此决定可逆，若后续收到大量真实反馈可再评估。

### 为未来泛化预留的扩展点（设计约束，非当前功能）

1. **内部概念留余量**：数据模型中"校区"本质是"锚定于高德地点的复刻目标"；地点类目（当前=学校类）作为字段存储，不散落硬编码。未来放开类目 = 调整筛选配置，而非改造数据结构。
2. **类目筛选配置化**：高德搜索结果的"只保留学校类"过滤规则集中定义在一处配置中，未来扩展为"任意地点类目"或"无筛选"时只改配置点。
3. **用户可见文案不含结构性假设**："校区""学校"等词已按 ADR-0005 外置为文本资源，未来产品更名/泛化时改文案文件即可。
4. 不做的事：不提前建"通用地点类型系统"、不提前抽象界面——避免为远期愿景支付当期复杂度。

## 后果

- 当前版本保持定位纯粹、实现最简。
- 未来泛化的改造范围收敛为：筛选配置、文案资源、若干界面调整；数据结构无需迁移。
