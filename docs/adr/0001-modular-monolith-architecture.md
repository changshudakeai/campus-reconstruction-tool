# ADR-0001：V2 采用模块化单体架构

## 状态

已接受（2026-07-25，产品负责人确认）

## 背景

v1.x 将全部代码放在一个紧耦合的 Cargo workspace 中，任何修改都触发大范围重新编译（实测 20-30 分钟），且模块间界限不清，小改动可能波及无关功能。产品负责人确认这是重写的首要动因。

曾考虑的备选方案：
- **保持现状仅优化编译**：无法根治耦合，被否决。
- **前后端分离/微服务**：用户需要维护多个进程，安装复杂化，且本产品是单机桌面工具，没有多端诉求，被否决。

## 决定

V2 采用**模块化单体**：最终交付仍是一个桌面应用（一个安装包、一个主程序），但内部按业务能力划分为边界清晰的独立模块（crate），模块之间只通过明确定义的接口通信。

模块划分原则：
- 每个核心能力一个模块：地基模式、Sponge V3 导出、项目持久化、地图集成。
- 界面层不包含业务逻辑；业务模块不依赖界面。
- 修改单个模块只需重新编译该模块，日常开发编译时间目标为分钟级以内。

## 后果

- 前期需要投入时间设计模块接口。
- 用户体验不变：仍是双击即用的单一应用。
- 为未来功能扩展提供隔离边界，避免 v1.x 的耦合恶化路径。
