# ADR-0031：通知中心与故障诊断分工——一个入口，说明与证据分离

## 状态

已接受（2026-07-29，产品负责人确认）

## 背景

ADR-0021 已把通知中心定为全应用唯一的消息账本，用于弹窗、短暂提示和历史通知。B11 诊断日志则原计划保存结构化日志、运行耗时和错误堆栈。两者都接触“错误”，如果各自建立面向用户的页面或把技术详情全部塞进通知中心，就会出现重复入口、重复记录和普通用户看不懂技术错误的问题。

当前代码已经出现这种混杂：桌面壳把错误对象转换成原始文字后直接交给通知中心；B11 尚未建立。

## 决定

### 一、通知中心是唯一的用户入口

- 不为 B11 新建与通知中心并列的故障列表、故障公告栏或独立诊断页面；
- 普通用户统一从通知中心查看错误；严重错误仍按 ADR-0021 先弹窗，并留底到通知中心；
- 通知内容使用普通用户能理解的语言，回答“发生了什么、有什么影响、下一步可以怎么做”，不默认展示错误堆栈等开发细节。

### 二、故障诊断在后台保存证据

- B11 负责开发人员排查所需的结构化日志、运行耗时、错误堆栈和相关运行证据；
- 每次需要诊断的错误生成一个故障编号，通知中心的用户说明与 B11 的诊断记录通过该编号关联；
- 通知中心不复制保存整份技术诊断，只保存用户说明、来源、时间和故障编号。

### 三、从错误通知导出故障资料

- 严重错误弹窗及其在通知中心中的留底记录提供“导出故障资料”；
- 每条可诊断错误由产生它的功能模块创建故障编号，并随页面结果返回一个不透明的“导出故障资料”操作；该功能模块拥有这次导出用例；
- 用户触发该操作时，S1 只通过统一的通知操作入口把不透明操作转交回原功能模块；S1 不解析故障编号、不直接调用 B11，也不拼装导出步骤；
- 原功能模块调用 B11 的一个完整接口；B11 内部完成证据读取、最少资料选择、脱敏、打包和文件写出，并返回成功或失败的呈现结果；
- 只有当原操作本身具有方案上下文，而且原功能模块已拥有完成该操作所需的方案数据时，才提供“包含当前方案数据”；原功能模块向 B11 提供经过授权的最小快照，B11 不查询正式项目数据库，也不持有正式业务数据；
- B7 只保存并显示入口、不透明操作、用户说明和结果通知，不调用 B11，也不读取诊断证据；
- B11 在这里是隐藏复杂实现的深模块，不向 S1 或功能模块暴露日志、脱敏和打包步骤。

### 四、默认最少资料与主动授权

- 默认故障资料只包含：软件版本、Windows 版本、故障编号、出错步骤和与该故障相关的运行记录；
- 导出前自动清除全部 Key、安全密钥、Windows 用户名和本地文件路径；
- 默认不包含校区名称、校区地址、边界坐标、方案名称和采集到的校园数据；
- 只有用户主动勾选“包含当前方案数据”后，才可把上述项目数据加入资料包；勾选时必须明确提示“其中可能包含校园位置”，不得默认勾选或静默加入；
- V2 只把故障资料生成到用户选择的本地位置，不自动上传、不在后台发送，也不要求账号或诊断服务器；用户自行决定是否通过其他方式发送给开发人员；
- 本地文件生成成功后短暂提示“故障资料已导出”；

### 五、内部故障记录留存

- B11 内部故障记录保留最近 30 天，同时设置 100 MB 总容量上限，任一限制先达到即自动清理最旧记录；
- 自动清理不弹确认，故障记录不属于用户方案数据；
- 用户已经导出到其他位置的故障资料文件不受 B11 管理，软件不得自动删除。

## 后果

- 用户只需要认识通知中心一个入口，不会面对两套故障列表；
- 同一次错误只产生一条用户通知和一份关联诊断，职责清楚且可追溯；
- 当前“错误详情原样透传通知中心”的实现需要改为用户说明与诊断证据分离；
- 故障资料生成必须经过统一脱敏，调用方不得各自拼装资料包；
- B11 不引入联网发送接口，排错功能不会扩大应用的网络与账号范围；
- 故障记录有明确的时间与容量上限，不会无限占用磁盘；
- B11 可以在不改变通知中心界面的前提下扩充排错能力。
