# ADR-0013：数据源可插拔——至少选一，按完整度/精细度推荐排序

## 状态

已接受（2026-07-25，产品负责人确认）

## 背景

v1.x 仅支持 OSM 与 Overture 两个数据源。产品负责人要求：未来可添加更多数据源；数据源对用户而言"至少选择一个"；选择过程中应用应给出推荐——根据各数据源在当前区域的数据完整程度、精细程度排序。

## 决定

### 数据源接入架构

1. 每个数据源实现为一个**独立适配器**：负责"查询指定区域 → 返回带标签的地理对象"这一件事；返回结果统一进入 ADR-0011 的标签映射与评审流程；
2. 新增数据源 = 新增一个适配器 + 在数据源清单登记，不改动采集、评审、生成、导出环节；
3. V2 首发内置：OSM、Overture 两个适配器（复用 v1.x 已验证的查询逻辑，按 ADR-0012 拉宽标签范围）。

### 用户侧选择规则

1. 采集前用户从数据源清单中**至少勾选一个**，可多选；
2. 应用对当前方案的边界区域**逐源评估并排序推荐**，评估维度：
   - **完整程度**：该区域内各类别对象数量；
   - **精细程度**：关键属性（层数/高度、名称、类别标签）的填充率；
   - 数据时点（数据集的新旧）作为次要参考；
3. 推荐结果以排序 + 简短理由呈现（如"推荐：本区域建筑数量最多，且 78% 带层数信息"），用户仍可自由勾选；
4. 多源同选时，重叠对象的去重与取舍沿用 v1.x"保留类型化证据、评审后合并"机制（v1.x ADR-0032），来源标签全程可见。

## 后果

- 数据源扩展成为常态化的小工作量操作，支撑 ADR-0009 的泛化愿景。
- 区域级评估需要在采集前对各源做一次轻量预查询，属可接受的一次性开销。
- 推荐算法的具体权重在实施阶段调校，但评估维度与呈现方式以本 ADR 为准。
