# ADR-0006：应用着陆流程——记住上次校区，落在方案列表

## 状态

已接受（2026-07-25，产品负责人确认）；2026-07-29 根据校区着陆流程访谈增补。

## 背景

首次流程已由 ADR-0004 确定（设置 → 选校区 → 方案列表 → 进方案）。本决策解决老用户再次打开应用时的着陆页问题。

v1.x 的做法是直接恢复上次工作现场，产品审计认定为阻断性问题："用户不知道之前完成了什么，也不知道如何重新开始"。

候选做法：
1. 每次都从选校区开始——流程一致，但绝大多数学生只有一个校区，每次多一次无意义点击；
2. 记住上次校区，直接落在该校区的方案列表；
3. 直接跳回上次编辑中的方案——重蹈 v1.x 覆辙，被否决。

## 决定

老用户打开应用后，**直接落在上次使用的校区的方案列表页**：

- 页面顶部显著展示当前校区名称；
- 顶部提供"切换校区"入口，一次点击可回到校区选择页；
- 校区选择页不拆分"列表"与"添加"两个页面：同一页面上方始终显示学校搜索框，下方显示"最近使用的校区"；点击其中任一校区即可进入其方案列表；
- "最近使用的校区"以卡片显示，卡片同时展示校区名称和地址；卡片主体用于进入校区，右侧放置独立的小叉用于"从最近使用中移除"；点击后立即移除，不弹确认窗口，只短暂提示"已从最近使用中移除"；该操作只清除快捷记录，不删除校区及其方案；
- "最近使用的校区"保留全部未被用户移除的记录，按最近进入时间倒序排列；内容超过页面时可向下滚动；
- v2.0.0 不提供"删除整个校区"功能；用户只能移除最近记录，或在校区内部按既有回收站规则处理具体方案；
- 不自动进入任何方案；由用户在方案列表中自行选择（列表展示各方案进度，帮助用户恢复上下文）；
- 若上次使用的校区记录不存在或不可用，退回校区选择页。

## 后果

- 方案列表页成为应用的"家"：常见情况零废操作，同时保留全局视野。
- 应用需持久化"上次使用的校区"这一状态（存入 app_settings）。
- 方案列表页承担"恢复上下文"职责，其信息设计（每个方案显示什么）需单独决策。
