# ADR-0008：校区通过高德搜索选定，而非自由命名

## 状态

已接受（2026-07-25，产品负责人确认）；2026-07-29 根据校区搜索流程访谈增补。

## 背景

最初的流程草案把"添加校区"设想为用户手动起名。产品负责人纠正：不可能去建一个不存在的学校，校区必须对应真实学校；用户在输入想复刻的学校名称时就应调用高德服务搜索，并对结果做筛选以避免混淆。

## 决定

添加校区的唯一途径是**搜索并选定真实学校**：

1. 校区选择页上方始终显示学校搜索框，下方显示"最近使用的校区"；不另设校区列表页、"添加校区"按钮或独立添加页面；没有使用记录时仅显示搜索区；
2. 用户输入学校名称关键词，应用调用高德地点搜索；
   - 用户点击"搜索"按钮或按回车键时开始搜索；输入过程中不自动刷新结果；
   - 搜索期间，搜索结果显示在搜索框下方，"最近使用的校区"暂时隐藏；清空搜索内容后，最近记录自动恢复；
3. **结果筛选**：只保留学校类地点（高校、中小学等教育类目），过滤掉以学校命名的公交站、地铁站、校门、银行网点等干扰项；同名/近名结果去重；
4. 候选列表每项展示：学校名称 + 所在地址（含行政区），多校区大学（如"华东师范大学(普陀校区)"与"(闵行校区)"）作为独立候选并列展示；
5. 用户点选一项后，系统以高德地点标识确认校区身份；尚未添加时建立校区，名称、坐标锚点均取自高德数据，用户不手动输入校区名；
6. 若该校区已经添加，系统不创建重复校区，直接选定原校区并短暂提示“该校区已添加，已为你切换”；
7. 这一次点选同时完成“添加或找到校区”和“选定当前校区”，随后立即进入该校区的方案列表，不返回校区列表要求用户再次点选；
8. 此后该校区下所有方案画边界时，地图直接定位到该锚点。
9. 网络中断或高德服务暂时不可用时，保留用户输入并停留在搜索页面，弹窗说明暂时无法搜索，提供“重试”和“取消”；取消后不创建校区，也不能绕过校区选择进入方案。

## 后果

- 校区名称规范、无错别字，多校区歧义在源头解决。
- 校区层持久化字段：高德地点标识、名称、地址、坐标锚点。
- 添加校区依赖网络与高德服务可用；网络或服务失败按上述弹窗规则处理；搜索无匹配结果按 ADR-0009 处理。
- 产品文案不使用"创建校区"；统一页面使用"搜索学校"与"最近使用的校区"，不提供"添加校区"按钮。
