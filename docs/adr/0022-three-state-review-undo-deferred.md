# ADR-0022：三态评审 + 撤销暂缓——状态本身就是后悔药

## 状态

已接受（2026-07-25，产品负责人确认）。本决策修订 ADR-0016（评审两态 → 三态、导出确认弹窗增加封账提示），并调整 ADR-0017 中 B8 模块的实施状态。

## 背景

访谈 B8（撤销重做）时正面处理它与已定评审流程（ADR-0016）的交叉：评审决定能否撤销、撤销能否穿越"导出=评审结束"这道门。

产品负责人提出关键改动：评审不止"保留/剔除"两态，应增加**"待定"**作为所有候选的初始状态——如此一来，误操作靠改状态即可自愈，评审台不再需要撤销机制；同时明确担忧撤销栈的实现复杂度。产品负责人另要求：因软件实际使用时间尚短，三态方案是否顺手未经验证，**撤销重做模块不裁撤，保留将来补建的接口与可能性**。

## 决定

### 一、评审改为三态（修订 ADR-0016）

| 状态 | 含义 | 导出时 |
|------|------|--------|
| **待定**（初始态） | 尚未人工裁决 | 不导出，也**不阻塞导出** |
| **保留** | 人工确认要 | **唯一被导出的状态** |
| **剔除** | 人工确认不要 | 不导出（无回收站，与 ADR-0016 一致） |

- 所有候选采集回来即为"待定"，人工逐个或批量裁决为保留/剔除；
- 点错了直接改点另一个状态即可，包括**批量改回待定**（恢复动作）；
- 六类抽屉（含"其他"）规则一致。

### 二、批量操作的确认规则（修订 ADR-0016）

| 批量操作 | 确认策略 |
|---------|---------|
| 批量**剔除** ≥5 项 | 二次确认弹窗（沿用 ADR-0016） |
| 批量剔除 1-4 项 | 直接执行 |
| 批量改为**保留**或**待定** | 不需确认（可自愈的无害动作） |

### 三、评审台不做撤销

三态自愈取代 Ctrl+Z：单个误操作重点一次，批量误操作批量改回待定。不实现撤销栈（避免撤销与批量操作、导出封账交织的复杂度与 bug 面）。

### 四、导出封账 + 影响告知弹窗（修订 ADR-0016 阶段二）

导出确认弹窗除类别汇总外，必须明示两件事（按 ADR-0021 弹窗铁律）：

1. **封账后果**："确认后评审就此结束，之前的评审决定不可再改；如需调整须重新采集、重新评审。"
2. **待定项报数**："尚有 N 项待定，它们不会被导出。"——如实告知、不拦截（待定不阻塞导出是产品负责人明确决定）。

### 五、B8 撤销重做模块：暂缓而非裁撤（调整 ADR-0017）

- v2.0.0 **不实现**撤销重做，B8 crate 不动工；
- 模块目录中**保留 B8 席位**，并在实施期预留接口可能性：评审状态变更等用户操作以**明确的状态变更操作**形式实现（而非散落的直接赋值），使将来补建命令历史层时无须翻修既有代码；
- 若三态方案实际使用不顺手，可重新提案启动 B8。

## 后果

- 评审台交互更直观：待定=还没看过，一眼可见哪些还没裁决；
- 无撤销栈，实现复杂度显著降低（呼应产品负责人的担忧）；
- 导出弹窗信息变多（汇总 + 封账后果 + 待定报数），文案须外置资源（ADR-0005）；
- "状态变更操作化"的接口预留是对实施期的架构约束，进入 B8/F5 相关工单的验收标准；
- ADR-0016 的两态表述以本决策为准；ADR-0017 的 B8 行状态改为"暂缓（预留接口）"。
