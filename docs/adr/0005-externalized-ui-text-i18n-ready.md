# ADR-0005：界面文本外置，多语言就绪设计

## 状态

已接受（2026-07-25，产品负责人提出并确认）

## 背景

V2 当前仅支持中文（见 ADR-0004），但产品负责人明确规划后续版本将加入多语言支持与多游戏版本支持，并要求从第一行代码起就为语言切换做好准备，避免未来"翻遍全部代码找中文字符串"的返工。

v1.x 的教训：中英文文案直接散落在界面代码与错误消息中（审计报告指出"英文界面混入中文错误正文""语言状态不可信"），事后清理成本极高。

## 决定

1. **所有用户可见文本一律外置**到集中的文本资源文件（按语言一个文件，如 `zh-CN`），界面代码只引用文本键（key），不出现任何硬编码的中文/英文字符串。
2. 覆盖范围包括：界面控件文字、提示与错误消息、通知内容、导出报告中的说明文字。日志与诊断记录等仅开发者可见的内容不要求外置。
3. 错误消息同样通过文本键生成，禁止在业务逻辑里拼接用户可见的句子。
4. 文本资源文件的加载机制从第一版就按"可切换"设计：新增一门语言 = 新增一个资源文件 + 在 ADR-0004 的语言下拉菜单中增加一项，不改动任何界面代码。
5. 带变量的文案（如"共 {n} 个建筑"）使用占位符插值，禁止用字符串拼接组句，避免未来其他语言语序不同导致返工。

## 后果

- 开发期每个新界面都必须同步登记文本键，纪律成本小但持续。
- 未来加英文（或其他语言）时，工作量收敛为"翻译一个文件"。
- 游戏版本相关的方块映射表同理按"版本 → 映射文件"组织，为多游戏版本支持预留同样的扩展路径。
