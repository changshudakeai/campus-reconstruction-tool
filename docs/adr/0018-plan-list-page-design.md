# ADR-0018：方案列表页信息设计——干净卡片 + 最近优先

## 状态

已接受（2026-07-25，产品负责人确认）；2026-07-29 根据方案与回收站流程访谈增补。

## 背景

方案列表页是应用的"家"（ADR-0006：老用户着陆于上次校区的方案列表页），承担"恢复上下文"职责——用户隔了两周回来，要在 3 秒内想起"我做到哪了、接下来该干哪个"。本决策确定每张方案卡片显示什么、列表怎么排、卡片上能直接做什么。

既有相关决策：轻创建与"尚未确定范围"状态（ADR-0010）、边界归方案且可复制（ADR-0007）、校园级回收站保留 30 天（v1.x 决策，本轮确认沿用）。

## 决定

### 一、卡片信息（三件套，保持干净）

每张方案卡片只显示三件信息：

1. **方案名**（如"方案 1 - 全景复刻"）；
2. **进度描述**：一句话说清"已完成什么 → 下一步是什么"，例如"已完成：边界、朝向、建筑采集 → 下一步：道路评审"；最早期状态如实显示"尚未确定范围"（ADR-0010）；
3. **最后修改时间**：相对表述（如"3 天前"）。

**明确不放**：地图缩略图（有缓存代价且早期方案无图可显）、导出状态（放进方案内部查看，不占卡片）。

### 二、排序：最近改过的排最前

按最后修改时间倒序。上次干活的方案永远在第一个，点开即继续，与列表页"恢复上下文"的职责一致。不提供手动排序。

### 三、卡片"···"菜单（三个操作）

不进方案即可对卡片操作：

| 操作 | 行为规则 |
|------|---------|
| **改名** | 弹出轻量对话框；同一校区内方案名不得重复（沿用 ADR-0010 校验规则） |
| **复制方案** | 完整复制（含边界、朝向、已做的采集与评审），新名自动加"副本"后缀；与 ADR-0007 的"仅复制边界"并存不冲突 |
| **删除** | 删除前先确认，确认后进入校园级回收站并保留 30 天；在回收站内立即永久删除需再次确认（沿用 v1.x 决策） |

回收站保留"清空回收站"操作：一次性永久删除当前校区回收站中的全部方案，不影响其他校区；执行前必须再次确认，并明确说明清空后不可恢复。

回收站列表按删除时间倒序排列（最近删除的排最前）；每项显示方案名、删除时间和剩余保留时间，并提供"恢复"与"立即永久删除"。

### 四、搜索：v2.0.0 不做

一个校区下方案通常 3-5 个，一屏可扫完。搜索属可逆决定，方案多到翻页时（v2.1+）再补。

### 五、恢复时的同名处理

从回收站恢复方案时，如果同一校区已经存在同名方案，系统自动为恢复方案添加"（恢复 1）"后缀；若仍重名则依次使用"（恢复 2）""（恢复 3）"。恢复过程零交互、不覆盖现有方案、不因重名阻断，也不弹窗要求用户先改名。

恢复成功后继续停留在回收站，并短暂提示"方案已恢复"；不自动跳回方案列表，也不直接打开刚恢复的方案。

"立即永久删除"成功后继续停留在回收站并短暂提示"方案已永久删除"；"清空回收站"成功后同样停留并提示"回收站已清空"。三种操作均不自动跳回方案列表。

## 后果

- 卡片信息极简，进度描述成为核心：实施时进度文案须由方案真实状态生成（与 ADR-0012 的"2 必经 + 6 可选 + 导出"任务链对应），文本走外置资源（ADR-0005）；
- "复制方案"要求整方案数据（边界、朝向、采集、评审状态）可整体拷贝，SQLite schema 设计需支持（关联 ADR-0002）；
- 回收站为校园级：删除的方案在"该校区"的回收站中恢复；恢复重名按上述"（恢复 N）"规则自动处理；
- F3 模块（project-management）的方案列表与回收站核心产品行为已完成访谈；字体、间距与按钮尺寸等视觉细节留待开发版界面审核。
