# ADR-0014：日常预览通过桌面快捷方式

## 状态

已接受（2026-07-25，产品负责人确认）

## 背景

v1.x 存在多套入口混用的情况：`start-app.cmd`（开发期直接运行）、双击 exe 安装包（完整安装流程）、PowerShell 验收脚本等。用户难以分辨何时该用哪个，导致体验混乱。V2 需要统一"日常预览"的打开方式，确保新版本随时可见且操作一致。

## 决定

1. **单一预览入口**：程序每次构建后自动生成一个固定快捷方式，名称为"**校园复刻工具 - 开发版**"，放置于桌面或任务栏；
2. **无需手动安装**：点击该快捷方式即可直接运行最新版本，不需要用户执行任何安装向导；
3. **版本更替策略**：新构建覆盖旧构建的同一位置，快捷方式始终指向最新内容；若新版本异常，保留上一个可用版本作为保底；
4. **正式发行分离**：未来若发布正式安装包，将创建另一个快捷方式，名为"**校园复刻工具 - 正式版**"，与开发版并存，互不影响。

### 命名规范

- **开发版**："校园复刻工具 - 开发版"（日常预览用，默认入口）
- **正式版**："校园复刻工具 - 正式版"（里程碑验收时使用）

### 实施要求

- 构建脚本需在每次编译完成后自动生成或更新快捷方式；
- 快捷方式图标需统一使用内置图标准保用户体验一致；
- 快捷方式仅用于本地预览，不做系统级注册（如开始菜单、注册表安装信息）。

## 原因

- **简化用户操作**：用户只需记住一个固定的入口，不用在多个命令之间选择；
- **降低认知负担**：无论内部如何更新，外部访问方式保持不变；
- **便于快速验证**：每次构建后无需额外步骤即可查看效果，提升迭代效率。

## 后果

- 用户每日预览路径稳定一致，避免 v1.x 式的入口混乱；
- 开发版与正式版将作为两个独立入口并存（未来），不会因正式安装而移除或覆盖开发版；
- 后续如需增加更多预览通道（如命令行参数切换），可在不破坏此约定的基础上扩展。
