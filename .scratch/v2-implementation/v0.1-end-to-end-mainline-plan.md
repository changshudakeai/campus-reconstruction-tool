### M1 — v0.1 边界直出（P0 后第一优先级）

- 边界保存成功后立即解锁导出，不要求自定义朝向、候选采集或评审。
- 未设置自定义朝向时，在一个完整导出用例入口内显式采用地图正北；不得把默认值伪装成用户已经设置过朝向。
- 空候选集合合法：生成边界覆盖的平整场地，经 B18 → B17 → B4 输出 `.schem` 和如实 manifest。
- S1 只提交“开始导出”意图并显示确认、进度、成功或失败；生成、版本核对和落盘不写回 S1。
- 验收测试至少覆盖：无自定义朝向、无候选、有效边界可以导出；无边界明确拒绝；写入失败不产生伪成功。
- 产品负责人可演示：选校区 → 建方案 → 圈边界 → 直接导出并看到文件。

M1 完成即达到 **v0.1 首个可用版**。

## 执行纪律

1. 同一时间只推进一个主线阶段；不得因为看到旧工单未完成就自动恢复它。
2. 用户可见行为以产品基线为准；技术实现可自行选择，但不得重新把朝向或候选变成导出前置。
3. 一个用户意图由一个用例入口负责到底；入口内部允许多能力、后台进度、取消和重试。
4. 功能横向依赖默认禁止但允许显式例外；新增边必须先证明职责内聚并加入白名单。
5. 数据完整性、状态迁移、公共接口、缺陷修复和 ADR 行为采用测试优先；纯展示、机械重构和探索原型可同步或事后补测试。
6. 单文件 1000 行保留带理由豁免的警戒线；不再按 crate 源文件数阻断，改看内聚性、公共 API、依赖扇出和编译时间。

### P1 插入缺陷：T50 采集可靠性（2026-08-17）

在继续剩余 V2.1 架构维护前，先完成并验收
`.scratch/v2-implementation/issues/T50-collection-acquisition-reliability.md`。原因是公共
Overpass/Nominatim 节点的负载波动已使六类候选连续失败；这属于现有边界获取与候选
采集能力的可靠性缺陷，不新增产品功能。T50 必须保持六类集中规则、真实边界资格、
原始证据永久保留和候选批次原子发布；客户端顺序有限重试仍不能达到可接受成功率时，
再以真实证据决定是否单独立项自建服务。T50 完成后回到下列 V2.1 执行顺序，不借机
扩大到 Overture 或自建后台。

本地实现已完成，真实网络候选与边界均连续 3/3 成功；产品负责人已验收并授权并入
