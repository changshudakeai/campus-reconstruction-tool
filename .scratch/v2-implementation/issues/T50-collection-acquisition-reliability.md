# T50 — 校区边界与候选采集可靠性

**Status:** completed（2026-08-17，产品负责人验收并授权并入本地主线）

**What to build:** 公共 OSM 服务负载波动时，校区边界获取与六类候选采集应在
一个有现实预算的后台操作内自动顺序切换节点、有限重试并给出阶段反馈。失败不得
覆盖上一完整候选批次；高德补名失败只留下部分未命名，不阻断已取得的 OSM 几何。

**Blocked by:** None。完成并验收后恢复 V2.1 剩余结构优化主线。

## 用户可见验收

- 采集仍在后台运行；当前节点繁忙时显示“正在自动切换备用节点”，取消仍可用。
- 网络最终失败或达到总体时间上限时，普通用户能看懂发生了什么，并知道已有完整
  候选保持不变、可以稍后重试。
- 校区边界不会用固定边界或假数据静默兜底；已确认边界恢复后不重复联网解析。
- 补名部分失败时，几何采集仍成功，报告如实标记“部分建筑未命名”。

## 数据与架构不变量

- selector 继续由 B13 集中标签规则生成；bbox 只缩小 Overpass 传输范围。
- WGS-84 → GCJ-02 后按真实方案多边形判定资格；仅合法边界内对象 Reviewable。
- 四个有界传输分片顺序执行；本次运行共享节点健康与冷却，禁止并发轰炸和无界重试。
- 原始观测永久保留；候选投影只在全部必要步骤成功后原子发布，失败时上一完整批次
  仍为当前批次。
- 不新增 schema，不引入自建后台、账号、费用或部署。

## 定向验证

- `data-acquisition`：分片覆盖、POST 请求体、前两节点失败第三节点成功、单节点超时、
  429/504/错误页/坏 JSON、退避/冷却、成功分片不重复、Nominatim 缓存与严格解析。
- `collection-flow`：总体截止贯穿拉取/补名/收尾、失败保留上一完整批次、补名部分失败
  不阻断几何、原始证据与候选原子发布不变量。
- `desktop-shell`：切换节点阶段真实呈现、UI 不冻结且可取消；采集失败重试回归。
- 真实网络：边界与六类候选各连续三轮，记录成功率、耗时与实际节点路径。

## 本窗口真实网络证据

- 六类候选连续 3 轮成功（修复前同一 live test 连续 3 轮均在约 15.01s 失败）：
  52.50s、60.78s、88.52s；三轮均取得 2546 个源对象，其中 815 个面、991 个已有名。
- 候选实际路径包含首节点直达、切到 kumi/mail.ru，以及失败分片仅重试失败节点；
  已成功分片没有重复下载。
- 校区边界连续 3 轮成功：3.89s、67.73s、11.17s；慢的一轮实际路径为
  de → kumi → mail.ru → de，最终仍返回上海交通大学（闵行校区）38 点边界。
- 当前样本已证明客户端方案可恢复，暂不需要自建服务；公共实例仍会波动，后续版本
  走查继续记录成功率，若稳定样本仍频繁耗尽 240s 总预算再单独评估自建。
