# T33 评审候选列表滚动/分页修复（T32-D2，M5 后置）

Status: completed（2026-08-17 发布收口）
Blocked by: 无（M5 收口不受影响；T32 已用空分类绕过完成封账）

## What to build（负责人视角）

真实走查发现：候选较多时（如 1026 个建筑），评审工作台候选列表没有滚动容器，“封账完成评审”等操作栏渲染在视口外，鼠标滚轮/键盘都无法到达，用户无法直接完成封账。修复后应能在大量候选下正常滚动浏览并完成操作。

## 缺陷事实（T32 走查实测）

- 1026 个候选（建筑 745 + 其他 276）下，“封账完成评审”操作栏在视口外不可达；本次通过切换到空分类（道路 0）绕过完成封账。
- 评审工作台页面（`apps/desktop/ui/review.slint` 或对应布局）缺少列表滚动/分页容器。

## 范围

1. 评审候选列表加滚动容器（或分页），候选多时操作栏始终可达。
2. 覆盖：列表滚动可用（滚轮/键盘）、操作栏（逐项判定/批量确认/封账）在大量候选下可见可点、分类切换后行为一致。
3. 不改评审/封账逻辑、不改产品基线；不开 GitHub Issues。

## 验收标准（逐条证据）

1. 大量候选（≥1000）下列表可滚动，操作栏可见可点（截图 + 可点性断言）。
2. 滚轮与键盘滚动均有效；分类切换后滚动状态合理。
3. 全部门禁全绿（Windows，`SLINT_BACKEND=software`、`CARGO_BUILD_JOBS=2`）。
4. 重建便携包并更新人工验收记录。
