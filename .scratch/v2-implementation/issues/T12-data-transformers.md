# T12 — B13 数据转换器（标签映射表 + 六类别归类）

**What to build:** 原始对象 → 已归类候选；由数据源标签驱动归类，集中定义的标签映射表决定归属；多标签冲突按 建筑 > 体育 > 水域 > 道路 > 植被 > 其他 取最高优先级；映射不上归"其他"禁止静默丢弃。

- **窗口契约**：缝 3（采集流水线 ↔ F4 → B12 → B13）。F4 向 B12 要原始对象后交给 B13 归类；B13 只依赖自身的标签映射表和 B1 的共享类型。
- **业务规则**：标签→类别映射表集中配置一处（呼应 ADR-0009 配置化原则）；与采集查询范围同源管理（ADR-0012）；"其他"是正式类别而非垃圾桶。
- **复用 v1.x**：v1.x `campus-services` 已有按 leisure/building 标签分类逻辑，V2 继承并修订映射表。

**Blocked by:** T01, T02（crate 框架 + 共享类型定义）

**Status:** completed

- [x] data-transformers crate 立项并实现标签映射表数据结构（tag_rules: [category, pattern]）
- [x] 映射表配置文件设计（yaml/json，包含建筑/道路/水域/植被/体育家族的常见 tag）
- [x] 归类引擎实现：给定原始对象 → 查映射表 → 返回类别（含优先级逻辑）
- [x] "其他"类兜底逻辑：未命中的标签不猜测、不丢弃、进"其他"并在评审队列可见
- [x] 标签映射表校验 API：确保所有五类都有至少一个 tag 规则、无规则导致静默丢弃
- [x] public-api 快照测试 + 初始快照入库
- [x] 单元测试：给定 building=supermarket + leisure=pitch → 断言归类为"体育"（优先级高于建筑）

## 负责人验收点（一句话）

把一堆原始对象丢进去，标签映射表说是什么类就是什么类，体育馆因为有 leisure=pitch 就归到体育而不是建筑，没有匹配标签的对象不会消失而是进"其他"这个抽屉。
